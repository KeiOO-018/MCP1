# MCP1 — 중세 성 액션 방탈출

**UE 5.8 · 1인 · 9일 (2026-08-27 ~ 09-04) · 블루프린트**

로비에서 시작해 방 셋을 차례로 클리어한다. 방에 들어가면 문이 봉인되고, 그 안의 적을
전부 쓰러뜨려야 다음 방의 열쇠가 떨어진다. 셋을 다 열면 2층 최종 문이 열린다.
방 안에서 죽으면 그 방만 초기화된다.

2025년 9인 팀 프로젝트 **Project ICI**의 T자 성 구조를, AI 도구를 쓰면서 혼자 다시 지은 것이다.

## 무엇을 만들었나

조작 — 이동 · 점프 · 시점 전환(`V`, 3인칭 ↔ 1인칭) · 습득(`F`) · 슬롯 선택(`1`/`2`/`3`) ·
사용(`E`) · 버리기(`Q`) · 공격(`LMB`)

| 시스템 | 핵심 |
|---|---|
| **인벤토리** | `S_ItemDef` 구조체 + `E_ItemNature` 열거형 + `DT_Items` 6행. 슬롯 3칸, 개수는 `SlotCount` 변수 하나. **선택이 곧 장착** |
| **상호작용·문** | `BPI_Interact` 인터페이스 하나. 문도 아이템도 **같은 라인트레이스 한 경로**. 상태 셋 — `bLocked` · `bOpen` · `bSealed` |
| **적 AI** | `BP_Enemy` 한 클래스. 시야각 + 라인 오브 사이트로 벽 너머 감지 차단. 추격 · 복귀 · 방 소속. **BehaviorTree를 안 썼다** |
| **전투** | 몽타주 노티파이로 타격 창을 열고 **칼날이 지나간 궤적을 스윕 트레이스**. 한 스윙에 같은 대상은 한 번만 |
| **진행** | `BP_StageRoom`이 자기 방의 적을 세고 열쇠를 떨군다. 방에서 죽으면 그 방만 초기화 |
| **HUD** | **UMG 위젯을 하나도 안 만들었다.** `AHUD` 캔버스로 슬롯 · HP 바 · 프롬프트를 전부 그림 |
| **아트** | 석재/목재 재질, 횃불 `BP_Torch` 18개. **기성 에셋 없이 기본 프리미티브로 조립** |

### 데이터가 규칙을 만든다

| | |
|---|---|
| ![](Portfolio/screenshots/04-door-locked.png) | ![](Portfolio/screenshots/05-door-opened.png) |
| 칼을 든 채 문 앞 → `DOOR IS LOCKED`. 3번 칸에 은열쇠가 **그대로 있다** | 은열쇠를 선택하고 같은 문 → 열림. 3번 칸이 **비었다** |

가방에 열쇠가 있어도 **선택하지 않으면 열리지 않는다.** 문 코드는 한 벌이고,
무엇이 열쇠인지는 `BP_Door.RequiredKey`와 DataTable 행이 정한다.

2025년 원본은 아이템이 열쇠 한 종이었고 `Item_Name` 문자열 비교로 식별했으며
문마다 전용 클래스가 있었다. **아이템을 늘리려면 그때는 코드를 고쳐야 했고, 지금은 행을 하나 추가하면 된다.**

## 어떻게 만들었나

**AI가 명령문을 쓰고, 사람이 실행하고 검증했다.** 그 작업 규칙을 파일로 고정한 것이
루트의 [`CLAUDE.md`](CLAUDE.md)다 — 심문 → 사양 → 구현 → 검증 순서, 새로 만들기 전에
거치는 결정 사다리, 그리고 **도구가 "성공"이라고 답해도 에디터에서 다시 확인한다**는 규칙.

`Docs/Terminal-Log/` 56건이 그 검증의 원문이다. 도구의 응답과 실제 상태가 어긋난
사례들이 그대로 남아 있다.
