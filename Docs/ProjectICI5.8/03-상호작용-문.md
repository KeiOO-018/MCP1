# 03 · 상호작용과 문

## 자료에 있는 것

### 라인트레이스 상호작용 (플레이어 쪽)

`ICI_Character`의 `LineTrace` 커스텀 이벤트. 입력은
`EnhancedInputAction ICI_Interaction`의 **`Started`** 핀.

```
Camera.Get World Location            → Start
Camera.Get Forward Vector × 300.0    → (+ Start) → End
  → Line Trace By Channel
       Trace Channel  : Visibility
       Draw Debug Type: For Duration      ← 디버그 잔재
       Ignore Self    : true
  → Branch(Out Hit)
  → Break Hit Result → Hit Actor
  → Does Implement Interface(Interface)
  → Branch
  → Door (인터페이스 메시지 호출)
```

- 사거리 **300**
- 자료 설명: "문, 기타 오브젝트와 상호작용하기 위해 제작된 라인 트레이스.
  블루프린트 인터페이스를 추가하여 상호작용이 가능한 대상을 늘릴 수 있다."
- `Draw Debug Type`이 `For Duration`으로 켜져 있다 — 배포본에서 디버그 선이 그려진다

### 문 `Stage2Door`

- 컴포넌트: `DefaultSceneRoot` → `ExitLockedMessage`, `EntryLockedMessage`, `Door1`
  - 안내 메시지 둘은 문 앞뒤에 각각 붙은 월드 텍스트다
    ("문이 잠겼습니다. / 열쇠가 필요합니다.")
- 변수: `Open`(bool), `Locked`(bool), **`KeyID`(Name)**, `PlayerREF`(ICI_Character),
  `IsLocked`(bool), `GameState`, `GameMode`
  - **`Locked`와 `IsLocked` 두 개가 따로 있다.** 자료에서 `IsLocked`가 쓰이는 그래프는
    확인되지 않았다
- 함수 23개 오버라이드 가능

### 문 상태 4종

자료 표기: "문의 열림, 닫힘, 잠김, 안잠김 상태를 변수로 선언하여 이후 기능 구현에
활용될 수 있도록 함." 실제로는 bool 두 개(`Open`, `Locked`)의 조합이다.

### 여닫기

```
OpenDoor(Initiate: bool)
  → Branch(Initiate)
      True  : Move Component To(Door1, Target Relative Rotation 0,0,-90, Over Time 0.0)
              → Set Open = true
      False : Move Component To(Door1, 같은 회전,
                                Ease Out + Ease In,
                                Over Time 1.0,
                                Force Shortest Rotation Path)
              → Set Open = true

CloseDoor
  → Move Component To(Door1, 원위치) → Set Open = false

LockDoor   → Set Locked = true
UnLockDoor → Set Locked = false
```

**`Initiate` 핀의 역할이 이것이다** — `true`면 `Over Time 0.0`으로 즉시 회전(연출 없음),
`false`면 1초 동안 부드럽게. 스테이지 리셋처럼 "상태만 맞추면 되는" 경우에 `true`를 쓴다.

### 리셋용 `Initiate` 이벤트

```
Initiate (Custom Event)
  → Branch(Open)
      True  : Open Door(Initiate = true)
      False : Close Door
```

### 상호작용 흐름

```
Event Door (인터페이스)
  → ToggleDoor
      → IsValid(Player REF)
          Not Valid : Get Player Character → Cast To ICI_Character → Set Player REF
      → Branch(GameMode.Is Stage 1 Clear?)
          False : 안내 UI 표시 (아래 참조)
          True  : Branch(Locked)
                    True  : 인벤토리 확인 → Item_Name == KeyID ?
                              True  : Un Lock Door → Open Door → Player.Use Key
                              False : 안내 UI 표시
                    False : Branch(Open) → Close Door / Open Door
```

### 안내 UI

```
Set Visibility(Entry/Exit Locked Message, true)
  → Delay 2.0
  → Set Visibility(false)
```

2초 표시 후 자동으로 숨긴다.

### 문이 스테이지 로직과 엮이는 지점

문은 `GameMode`가 직접 하드 참조로 조작한다
([05-진행구조.md](05-진행구조.md) 참조). 각 스테이지 이벤트가
`Stage 1Door` / `Stage 2Door` / `Stage 3Door` 변수를 각각 들고
`Close Door` → `Lock Door`를 부른다.

## 다시 만들면 (내 의견)

### 1. 상호작용의 뼈대는 살아 있다 — 여기가 원본에서 가장 잘 만든 부분이다

`라인트레이스 → Does Implement Interface → 인터페이스 메시지` 는 정석이다.
카메라 기준으로 쏘고, 인터페이스로 대상을 넓힐 수 있게 열어뒀다.
**이 구조는 그대로 가져가도 된다.**

문제는 이 구조를 문에만 썼다는 것이다. 아이템은 별도로 오버랩 + `Enable Input`을 쓴다
([02-아이템-인벤토리.md](02-아이템-인벤토리.md) 4번).
**재구성하면 아이템·문·상자·레버를 전부 이 인터페이스 하나에 태운다.**
그게 원본 자료가 직접 적어둔 의도이기도 하다.

### 2. 인터페이스 함수 이름이 `Door`다

인터페이스에 대상 이름을 박으면 다음 대상(상자, 레버)이 생겼을 때
함수를 또 만들게 된다. `Interact` 같은 동작 이름으로 바꾼다.
반환값으로 "상호작용 가능한지"와 "화면에 뭐라고 띄울지"를 돌려주면
크로스헤어 하이라이트도 같은 경로로 처리된다.

### 3. 문이 GameMode를 직접 캐스팅해 스테이지 상태를 묻는다

`GameMode.Is Stage 1 Clear?` — **`Stage2Door`가 1스테이지 클리어 여부를 안다.**
문마다 어느 스테이지를 봐야 하는지가 그래프에 박혀 있다.
문에 "내가 요구하는 선행 조건" 변수를 두고 인스턴스에서 지정하면
문 블루프린트는 하나로 끝난다. 지금은 `Stage2Door`라는 이름부터가
"2번 문 전용"이다.

### 4. `Locked` / `IsLocked` 중복

같은 뜻으로 보이는 bool이 둘 있다. 하나는 죽은 변수일 가능성이 높다.
**이름 비슷한 변수 두 개는 나중에 반드시 잘못 쓴다.**
재구성 시 상태를 하나로 정리하거나, 애초에 enum(`Closed`/`Open`/`Locked`)으로 만든다.

### 5. `Draw Debug Type: For Duration`

배포본에 디버그 선이 그려진다. 재구성 시 `None`으로 두고,
디버그가 필요하면 콘솔 변수나 에디터 전용 분기로 뺀다.

### 6. `Delay 2.0` 안내 UI

`Delay`로 만든 표시/숨김은 연속으로 여러 번 상호작용하면 타이밍이 겹친다
(먼저 건 `Delay`가 나중에 켠 메시지를 꺼버린다). 재구성 시
`Set Timer by Event` + 기존 타이머 초기화, 또는 위젯 애니메이션으로 바꾼다.
사소하지만 실제로 눈에 보이는 버그다.

### 7. 사거리 300은 어디서 왔는가

자료에 근거가 없다. 손으로 맞춘 값일 가능성이 높으므로
**재구성 시 임의로 바꾸지 않는다.** 인스턴스 편집 가능 변수로 빼고 기본값 300을 유지한다.
