# 02 · 아이템과 인벤토리

사용자가 정한 재구성 1순위. 원본에서 가장 얇은 부분이기도 하다.

## 자료에 있는 것

### 구조체 `ItemDetails`

아이템 하나의 정보를 담는 구조체. **인벤토리의 유일한 데이터 단위다.**

| 필드 | 타입 | 기본값 |
|---|---|---|
| `Item_Name` | Name | `None` |
| `Item_Icon` | Texture 2D | `T_EV_BlankWhite_01` |
| `Item_Nature` | enum `Item Type` | `Stage_Key` |
| `Item_Empty` | Boolean | `true` |
| `Item_Class` | class (`ICI Master Item`) | `ICI_Empty` |

실제 값이 채워진 예 (자료의 인스턴스 스크린샷):

| 필드 | 값 |
|---|---|
| `Item_Name` | `Stage2_Key` |
| `Item_Icon` | `KakaoTalk_20250901_171934761` |
| `Item_Nature` | `Stage_Key` |
| `Item_Empty` | `false` (체크 해제) |
| `Item_Class` | `ICI_MasterItem` |

- `Item Type` enum은 자료에서 **`Stage_Key` 한 값만 확인된다.** 다른 값이 있는지는 확인 안 됨
- `Item_Empty`가 `true`이고 `Item_Class`가 `ICI_Empty`인 것이 "빈 칸"의 표현이다
- **아이콘 텍스처 이름이 `KakaoTalk_20250901_171934761`이다.**
  카카오톡으로 주고받은 이미지를 그대로 임포트해 쓴 것

### 액터 `ICI_MasterItem`

월드에 놓이는 아이템의 베이스 블루프린트.

- 컴포넌트: `Collision`, `Widget`
- `Event BeginPlay` → `Get Player Character` → `Cast To ICI_Character` → `Set Character REF`
- `On Component Begin Overlap (Collision)`
  → `Set Visibility(Widget, true)`
  → `IsValid(Character REF)` — 유효하지 않으면 `Get Player Character` → `Cast` → `Set Character REF`
  → `Set Item Info`, `Set Character REF`
  → **`Enable Input(self, Get Player Controller)`**
- `On Component End Overlap (Collision)` → 위의 역순, 마지막에 `Disable Input`
- 습득 안내는 월드 위젯 — 인게임 화면에 `Press E to Pick Up`으로 뜬다.
  콜리전에 겹쳐 있는 동안만 보이고 벗어나면 사라진다

### 플레이어가 가진 인벤토리

`ICI_Character`의 변수 두 개가 인벤토리의 전부다.

- `Item Info Array` — `ItemDetails` 배열
- `Selected Slots` — int. 현재 선택된 슬롯 번호

### `Use Key` 함수 (플레이어)

```
GET(Item Info Array, Selected Slots)
  → Break ItemDetails → Item_Empty
  → Branch
      True  : (아무것도 안 함)
      False : Set Array Elem(Item Info Array[Selected Slots] = Empty Item)
              → Break ItemDetails(Empty Item).Item_Icon
              → Game HUD.Set Icon(Current Slot, Item Icon)
```

즉 **사용 = 그 칸을 빈 아이템 구조체로 덮어쓰고 아이콘을 흰 텍스처로 되돌리는 것.**
아이템 액터를 파괴하는 것이 아니다 (액터는 습득 시점에 이미 사라진다).

### 문이 인벤토리를 확인하는 방식

```
Player REF.Item Info Array
  → GET(Selected Slots)
  → Break ItemDetails → Item_Name
  → (Item_Name == Door.KeyID)   ← Name 비교
  → Branch → Locked 확인 → Open
```

**선택된 슬롯 한 칸만 본다.** 배열 전체를 뒤지지 않는다.
즉 열쇠를 가지고 있어도 **그 슬롯을 선택하지 않았으면 문이 안 열린다.**

### 열쇠 스폰

`ICI_GameMode.Drop Key`:

```
Branch(GameState.Remain Enemy == 0)
  → Switch on Int(Current Stage)
      1 : Get Actor Of Class(BP_ICI_Skeleton)   → Get Actor Transform → SpawnActor ICI Stage 2 Key
      2 : Get Actor Of Class(BP_ICI_Skeleton 2) → Get Actor Transform → SpawnActor ICI Stage 3 Key
```

- **자료 본문의 설명과 그래프가 어긋난다.** 본문은 "몬스터가 Is Dead 상태가 되고
  Destroy되기 전에 해당 위치를 저장. 현재 스테이지의 몬스터가 0명이 되면 해당 위치로
  알맞는 열쇠를 스폰"이라고 적었다. 실제로 `BP_ICI_Skeleton`에는
  `Stage1LastEnemyTransform` 변수가 있고 사망 시 `Delay 4.0` 뒤에 자기 트랜스폼을
  저장한다. **그런데 `Drop Key` 그래프는 그 변수를 쓰지 않고
  `Get Actor Of Class`로 아무 스켈레톤이나 하나 잡아 그 위치를 쓴다.**
  둘 중 어느 쪽이 최종본인지는 이 자료만으로 확인 안 됨
- 열쇠 클래스가 스테이지마다 별개다 — `ICI Stage 2 Key`, `ICI Stage 3 Key`,
  `ICI_Stage2_Key`, `ICI_Stage3_Key`

### 리셋 시 열쇠 처리

`Reset Current Stage` 안에서 `IsValid(ICI_StageN_Key)` → `Get Actor Of Class` →
`Destroy Actor`. 스테이지를 되감을 때 이미 떨어진 열쇠를 지운다.

자료에 적힌 자체 관찰:

> 열쇠 스폰을 구현하던 중, 클리어가 아닌 리스폰 시에도 열쇠가 스폰한다는 문제를 인식.
> **스폰 후 플레이어가 인식하기 전에 파괴하는 것으로 처리.**

### HUD 쪽 슬롯

`ICI_Cha_Main_Widget` 안의 인벤토리 UI.

- 계층: `[UI_Inventory]` → `Inventory box` → `SlotBorder0` → `SlotIcon0`,
  `SlotBorder1` → `SlotIcon1`
- **슬롯은 2칸뿐이다**
- `ChangeSlot(Current Slot)` — `Switch on Int` 0/1 → `Set Brush Color`로
  선택된 쪽 테두리를 빨강, 나머지를 흰색으로
- `SetIcon(Current Slot, Item Icon)` — `Switch on Int` 0/1 →
  `Set Brush from Texture(SlotIcon0 / SlotIcon1, Match Size)`

## 다시 만들면 (내 의견)

### 1. 슬롯 개수와 아이템 종류가 코드에 박혀 있다

`ChangeSlot`과 `SetIcon`이 둘 다 `Switch on Int`로 0과 1을 직접 나눈다.
슬롯을 3칸으로 늘리려면 두 함수를 모두 고치고 위젯도 손으로 하나 더 만들어야 한다.
`Drop Key`와 `Reset Current Stage`도 스테이지마다 `Switch on Int` 가지를 하나씩 갖는다.

MCP1에는 이미 **1/2/3 키로 고르는 3칸 슬롯 HUD**가 있다
(`Docs/AI-Log/2026-08-28-inventory-hud.md`). 이것도 같은 함정을 반복하지 않으려면
슬롯을 **배열 + `Uniform Grid` 또는 `Wrap Box`에 위젯을 런타임 생성**하는 쪽으로 가야 한다.
칸 수가 변수 하나로 결정되어야 한다.

### 2. `Name` 문자열 비교가 아이템 식별의 유일한 수단이다

`Item_Name == KeyID`. 오타 하나로 조용히 안 열린다. 컴파일 에러도 안 난다.
`Item_Nature`라는 enum이 이미 있는데 식별에는 안 쓰인다.

**대안 셋 중 하나를 골라야 한다:**

- **A. enum 확장** — `Item Type`에 값을 늘리고 문은 `Item Type`으로 매칭.
  가장 싸다. 아이템 종류가 10개 안쪽이면 충분
- **B. DataTable + RowName** — 아이템 정의를 표로 빼고 구조체는 RowName만 든다.
  아이콘·이름·설명·스택 여부를 한 곳에서 관리. 종류가 늘어날 때 가장 편하다
- **C. Primary Data Asset** — 가장 UE다운 방식이지만 지금 규모에 과하다

**B를 권한다.** 이번 재구성의 목표가 "아이템 종류를 늘리는 것"이라면
아이템 정의가 있어야 할 자리는 표다. 다만 이건 결정 사항이므로 사용자가 고른다.

### 3. 선택된 슬롯 한 칸만 보는 것은 게임 디자인 결정인가, 버그인가

문이 `GET(Selected Slots)` 한 칸만 확인한다. 열쇠를 들고 있어도 다른 칸을
선택 중이면 "열쇠가 필요합니다"가 뜬다. 이게 의도라면
"올바른 아이템을 골라서 쓴다"는 조작이 되고, 의도가 아니면 그냥 불친절한 버그다.

**자료에는 이 선택에 대한 설명이 없다.** 재구성할 때 먼저 정해야 한다 —
① 배열 전체를 검색해 자동으로 쓰는가, ② 지금처럼 선택한 칸만 쓰는가.
방탈출이라면 ②가 오히려 맞다. 다만 그렇다면 UI가 "무엇을 들고 있는지"를
훨씬 분명히 보여줘야 한다.

### 4. `Enable Input` / `Disable Input`을 아이템 액터마다 켜고 끈다

`ICI_MasterItem`이 오버랩 때마다 자기 자신에게 `Enable Input`을 건다.
아이템 두 개가 겹쳐 있으면 어느 쪽이 입력을 먹는지 불확실하다.
플레이어에는 이미 **라인트레이스 + BP 인터페이스** 상호작용이 따로 있다
([03-상호작용-문.md](03-상호작용-문.md)). **상호작용 경로가 두 개다.**

재구성하면 라인트레이스 하나로 통일한다. 아이템도 문과 같은 인터페이스를 구현하면
습득·개방·조사가 전부 같은 입력 하나로 처리된다. 원본에도 그 문장이 있다 —
"블루프린트 인터페이스를 추가하여 상호작용이 가능한 대상을 늘릴 수 있다."
**설계는 있었는데 아이템에는 적용이 안 됐다.**

### 5. 아이콘 텍스처가 카카오톡 파일명이다

`KakaoTalk_20250901_171934761`. 기능에는 문제가 없지만 포트폴리오에 그대로 남는다.
재구성 시 애셋 명명 규칙을 먼저 정하고 시작한다.

### 6. 재구성 시 정해야 할 것 (사용자 결정)

- 슬롯 몇 칸인가. 고정인가 확장 가능한가
- 아이템 식별을 무엇으로 하는가 (위 A/B/C)
- 아이템 종류를 몇 가지로 늘리는가. **여기가 이번 작업의 핵심이다.**
  열쇠 외에 무엇이 있는가 — 회복, 무기, 단서, 조합 재료?
- 스택(수량)이 있는가. 없으면 구조체가 훨씬 간단해진다
- 아이템을 버릴 수 있는가. `DropItemLoc` 소켓이 플레이어에 이미 있다
  ([06-플레이어-UI.md](06-플레이어-UI.md)) — 원본에서 쓰인 흔적은 자료에 없다
