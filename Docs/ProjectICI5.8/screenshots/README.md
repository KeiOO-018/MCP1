## 03-door-open.png — 문을 통과하는 중

- 문짝이 화면 왼쪽으로 물러나 있고 가운데가 뚫려 안쪽 방이 보인다
- **안쪽에 긴 탁자와 벤치가 있다.** `01-게임-개요.md`의
  "방 3개는 **식당** / 훈련장 / 감옥"에서 식당으로 보인다
- 안쪽 조명은 로비보다 훨씬 어둡고 회색 톤이다. 방 안쪽에 아치가 더 보인다
- 모션 블러가 강하다
- `80.13 FPS / 12.48 ms`

**이 한 장으로는 미닫이인지 여닫이인지 구분이 안 됐다.**
사용자가 **경첩 회전**이라고 확인해줬다. 그리고 다시 만들 때는
**경첩을 반대쪽으로** 하고 싶다고 했다 — 지금은 왼쪽 경첩이고, 오른쪽 경첩을 원한다.

## 이 세 장이 정한 것

`Docs/Spec/2026-08-30-문과-상호작용.md`의 입력이 됐다.

- 문은 **경첩 회전**이다. 미닫이가 아니다
- 경첩 쪽을 뒤집을 수 있어야 한다 → `bHingeOnRight` 인스턴스 변수
- 문 앞에 안내가 없던 것이 원본의 약점이었다 → 잠긴 문에 안내를 붙인다
- 1인칭에서 양손이 보이는 것이 목표 화면이다 → 카메라 작업이 칼보다 먼저다

## 더 찍으면 값이 큰 프레임

우선순위 순. 아직 없다.

1. **열쇠를 획득하는 순간** — 화면에 뭐가 뜨는지, 슬롯이 어떻게 채워지는지
2. **잠긴 문을 열쇠로 여는 순간** — 열쇠를 든 채 문 앞에 섰을 때의 화면
3. **방 하나의 전경** — 적 5명이 배치된 공간의 크기
4. **전투 중 한 장** — 칼을 휘두르는 순간의 손·칼 위치
5. **좌우 아치 안쪽** — 나머지 두 방의 입구
