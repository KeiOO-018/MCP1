# 06 · 플레이어와 UI

## 자료에 있는 것 — 플레이어 `ICI_Character`

### 컴포넌트 구성

```
ICI_Character (셀프)
└ 캡슐 컴포넌트 (CollisionCylinder)      캡슐 절반 높이 88.0 / 반경 34.0
  └ Camera
    └ SkeletalMesh
      ├ PlayerCollision
      ├ PlayerSword
      │ └ PlayerSwordCollision
      ├ DropItemLoc
      └ DeathCam
  ├ 메시 (CharacterMesh0)
  └ 화살표 컴포넌트 (Arrow)
  캐릭터 무브먼트 (CharMoveComp)
```

- **카메라 아래에 손·검 메시가 달린 1인칭 구조.**
  MCP1에서 지금 겪고 있는 "카메라가 head 본에 붙어 손이 안 보인다" 문제와
  정반대 구조다 — 여기선 메시가 카메라의 자식이다
- `DropItemLoc` — 아이템을 떨어뜨릴 위치용 소켓으로 보인다.
  **자료에서 이걸 실제로 쓰는 그래프는 확인되지 않았다**
- `DeathCam` — 사망 시 전환할 카메라

### 그래프와 함수

- 그래프: `EventGraph`, `AttackAndDeathGraph`
- 함수 33개 오버라이드 가능. 그중 확인된 것:
  `ConstructionScript`, `EnableSwordCollision`, `DisableSwordCollision`
- 매크로: `StopRuning`, `StartRuning`, `ManageStaminaDrain`, `ManageStaminaRecharge`
  (`Runing` 오타가 애셋 이름에 그대로 들어가 있다)
- 변수(확인된 것): `Speed`, `HP`, `Current HP`, `Max HP`, `Player SP`, `Run Cost`,
  `Stamina Recharge Rate`, `Stamina Manager Name`, `Is Running`, `Is Attacking`,
  `Press Attack Button`, `Hit Actors During Swing`, `Is Dead`,
  `Item Info Array`, `Selected Slots`, `Player REF`, `Attack Damage`

### 입력 — Enhanced Input

| 액션 | 처리 |
|---|---|
| `ICI_Move` | `Get Actor Right Vector` / `Get Actor Forward Vector` → `Add Movement Input` ×2 |
| `ICI_Jump` | Triggered → `Jump`, Completed → `Stop Jumping` |
| `ICI_Look` | `Add Controller Yaw Input` → `Add Controller Pitch Input` |
| `ICI_Attack` | Started → `Set Press Attack Button = true` → `Attack`, Completed → `false` |
| `ICI_Run` | Triggered → 스태미나 판정 → `Start Runing`, Completed → `Stop Runing` |
| `ICI_Interaction` | Started → `Line Trace` ([03-상호작용-문.md](03-상호작용-문.md)) |

### 스태미나

`Player SP`는 **0.0 ~ 1.0 정규화 값**이다 (회복 상한이 `MIN(SP + Rate, 1.0)`).

달리기 진입 판정:

```
( (Player SP > Run Cost) OR Nearly Equal(Player SP, Run Cost, 0.000001) )
  → ICI_Run Triggered → Branch
       True  : Start Runing (매크로)
       False : —
  → ICI_Run Completed → Stop Runing
```

관리 루프:

```
ManageSP (Custom Event)
  → Branch(Is Running)
      True  : Manage Stamina Drain
      False : Manage Stamina Recharge
```

`Manage Stamina Drain` 매크로:

```
Get Velocity → Vector Length Squared > 0.0
  AND  Player SP > 0.0
  → Branch
      True  : Set Player SP = MAX(Player SP - Run Cost, 0.0)
      False : Stop Runing
```

`Manage Stamina Recharge` 매크로:

```
Nearly Equal(Player SP, 1.0, 0.000001)
  → Branch
      True  : Clear Timer by Function Name(Object: self, Function Name: Stamina Manager Name)
      False : Set Player SP = MIN(Player SP + Stamina Recharge Rate, 1.0)
```

`Stamina Manager Name`이라는 Name 변수로 타이머를 건다 —
즉 `ManageSP`는 **타이머로 반복 호출된다.** (`Set Timer` 쪽 그래프는 자료에 없음.
**확인 안 됨**)

### 공격

```
Attack (Custom Event)
  → Set Is Attacking = true
  → Branch
      True → Play Montage(AM_PlayerAttack)
               In Skeletal Mesh Component : Skeletal Mesh
               Play Rate       : 0.9
               Starting Section: "Start"
             → Delay 1.1 → (Do Once Reset)
      Do Once 로 중복 재생 차단
```

검 판정:

```
On Component Begin Overlap (PlayerSwordCollision)
  → Cast To BP_ICI_SkeletonBase
  → Branch( NOT (Hit Actors During Swing CONTAINS Other Actor) )      ← "중복공격 방지"
  → Apply Damage(Damaged Actor: 스켈레톤,
                 Base Damage: Attack Damage,
                 Event Instigator: Get Controller,
                 Damage Causer: Self)
  → ADD(Hit Actors During Swing, Other Actor)
```

플레이어 AnimBP의 노티파이:

```
AnimNotify_StartAttck        ← 애셋 이름에 오타("Attck")
  → Try Get Pawn Owner → Cast To ICI_Character
  → CLEAR(Hit Actors During Swing)
  → Set Collision Enabled(Player Sword Collision, Query Only (No Physics Collision))

AnimNotify_EndAttack
  → Set Collision Enabled(Player Sword Collision, No Collision)
```

### 피격과 사망

```
Event AnyDamage
  → Set Current HP = Clamp(Current HP - Damage, 0.0, Max HP)
  → Branch(Current HP <= 0.0)
  → Death(self)
  → Cast To ICI_GameMode(Get Game Mode)   → Set ICI Game Mode
  → Cast To ICI_GameState(Get Game State) → Set ICI Game State
  → Delay 7.0
  → Stop Camera Fade(Get Player Camera Manager)
  → ICI Game Mode.Re Spawn
  → Destroy Actor(self)
  → [스테이지 초기화] Set Is Player Dead = true, (AND Start Stage) → Branch → …
```

`Death` 커스텀 이벤트:

```
Detach From Component(Camera, Location/Rotation/Scale Rule: Keep World, Call Modify ✔)
  → Set Is Dead = true
  → Disable Input
  → Set Active(Camera,   New Active ☐)      ← 기존 카메라 끔
  → Set Active(DeathCam, New Active ✔)      ← 사망 카메라 켬
  → Start Camera Fade(From 0.3 → To 1.0, Duration 7.0)
  → Play Montage(ICI_Death_Montage, Play Rate 1.0)
```

### 리스폰 착지 `BeginLanding`

```
BeginLanding (Custom Event)
  → 타임라인 (트랙: Landing)
      Update → Line Trace By Channel
                 Trace Channel : Visibility
                 Ignore Self   : ✔
                 Start / End   : X 0.0  Y 0.0  Z 0.0     ← 스크린샷상 값이 0
             → Get Actor Location → Lerp (Vector) → Set Actor Location
      Finished → Set Movement Mode(Character Movement, Walking)
```

자료 설명은 "캐릭터 위치에서 아래 방향으로 레이저를 쏴서 바닥 찾기"인데
**스크린샷의 Start/End 핀은 0,0,0으로 비어 있다.** 연결이 안 된 상태의 스샷인지
실제로 비어 있는지는 **확인 안 됨.**

## 자료에 있는 것 — UI

### 위젯 `ICI_Cha_Main_Widget` 계층

```
[ICI_Cha_Main_Widget]
├ [UI_Inventory]
│ └ Inventory box
│   ├ SlotBorder0 → SlotIcon0
│   └ SlotBorder1 → SlotIcon1
├ ICI_Cha_Widget_Toggle
├ PlayerHealth      (프로그레스 바, 빨강)
├ PlayerStamina     (프로그레스 바, 초록)
└ [Debug and Stage Info]
  ├ [UI_CurrentStage]   "Current Stage"
  ├ [CurrentStage]      "00"
  ├ [UI_Remain/Current] " / "
  ├ [RemainEnemy]       "0"
  ├ [CurrentEnemy]      "0"
  ├ [UI_StartStage]     "StartStage"
  └ StartStage          (체크 박스)
```

**섹션 이름이 `[Debug and Stage Info]`다** — 스테이지 정보 표시가
디버그 UI와 한 덩어리로 묶여 있다.

### 바인딩 함수

| 함수 | 내용 |
|---|---|
| `Get Current Enemy Text` | GameState.`Current Enemy` → `To Text (Integer)` |
| `Get Remain Enemy Text` | GameState.`Remain Enemy` → `To Text (Integer)` |
| `Get Current Stage Text` | `Current Stage == 4` → `"Clear"` / 아니면 `To Text (Integer)` |
| `Get Start Stage Checked State` | `Start Stage` → `Checked` / `Unchecked` |

`Current Stage == 4`가 클리어 조건 — **스테이지 3개라는 사실이 UI에도 박혀 있다.**

### 인벤토리 슬롯 조작

```
ChangeSlot(Current Slot)
  → Switch on Int
      0 : Set Brush Color(Slot Border 0, 빨강) → Set Brush Color(Slot Border 1, 흰색)
      1 : Set Brush Color(Slot Border 1, 빨강) → Set Brush Color(Slot Border 0, 흰색)

SetIcon(Current Slot, Item Icon)
  → Switch on Int
      0 : Set Brush from Texture(Slot Icon 0, Item Icon, Match Size ✔)
      1 : Set Brush from Texture(Slot Icon 1, Item Icon, Match Size ✔)
```

### 실제 인게임 화면

- 좌상단: `HP` 빨강 바, `SP` 초록 바 (라벨이 그냥 텍스트)
- 좌측 중앙: `Current Stage 1`, 큰 글씨 `0 / 0`, `StartStage ☐`
- 화면 중앙: 작은 흰 사각형 크로스헤어
- 하단 중앙: 슬롯 2칸 (선택된 칸이 빨간 테두리)
- 아이템 근처: `Press E to Pick Up`

## 다시 만들면 (내 의견)

### 1. 1인칭 카메라 구조는 원본 쪽이 낫다

`캡슐 → Camera → SkeletalMesh`. 메시가 카메라의 자식이라
**손과 검이 항상 화면에 있다.** MCP1의 현재 문제(카메라가 `head` 본에 붙어
손이 안 보임)는 원본에는 없던 문제다.

MCP1 재구성 시 카메라를 본에 붙이지 말고 이 구조를 따르는 것을 권한다.
`Docs/AI-Log/2026-08-28-inventory-hud.md`의 "칼로 가기 전에 카메라 작업을 먼저 한다"
항목에 대한 답이 여기 있다.

### 2. 디버그가 UI에 섞여 있다

`[Debug and Stage Info]`는 이름이 정직하다 — 스테이지 정보 UI가 디버그 표시다.
`0 / 0`, `StartStage ☐` 체크박스는 플레이어에게 보여줄 정보가 아니라
개발자가 보던 것이다. 재구성 시 **플레이어용 HUD와 디버그 오버레이를 분리한다.**
남은 적 수는 남겨도 좋지만 체크박스는 아니다.

### 3. 슬롯 UI가 슬롯 개수를 코드에 담고 있다

`ChangeSlot`, `SetIcon` 둘 다 `Switch on Int` 0/1.
([02-아이템-인벤토리.md](02-아이템-인벤토리.md) 1번과 같은 문제)

### 4. `Play Montage` 뒤의 `Delay 1.1`이 몽타주 길이를 대신한다

몽타주 길이가 바뀌면 이 숫자를 손으로 맞춰야 한다.
`Play Montage` 노드의 `On Completed` / `On Blend Out` 출력 핀이 이미 있는데
쓰이지 않고 `Delay`로 대체돼 있다.
**재구성 시 `On Completed`를 쓴다.** 값 하나가 사라진다.

(다만 `Play Rate 0.9`와 `Delay 1.1`은 손으로 맞춘 값이므로,
원본을 그대로 옮길 때는 건드리지 않는다)

### 5. 스태미나가 0~1 정규화인데 `Run Cost`가 호출당 소모다

`Manage Stamina Drain`이 타이머로 돌면서 `SP - Run Cost`를 한다.
타이머 간격이 바뀌면 소모 속도가 통째로 바뀐다.
초당 소모율로 바꾸고 델타를 곱하는 쪽이 안전하지만,
**이건 값의 의미가 바뀌는 변경이라 원본을 옮길 땐 하지 않는다.**
5.8에서 새로 만들 때 정한다.

### 6. `Runing`, `StartAttck` 오타가 애셋 이름에 박혀 있다

매크로 `StartRuning` / `StopRuning`, 노티파이 `AnimNotify_StartAttck`.
**이름을 바꾸면 참조가 조용히 끊긴다** (특히 AnimNotify는 애님 시퀀스에 이름으로 박힌다).
원본에서는 건드리지 않는 게 맞고, **5.8에서 새로 만들 때 올바른 이름으로 시작한다.**

### 7. `DropItemLoc`이 쓰이지 않는 것으로 보인다

컴포넌트는 있는데 자료 어디에서도 참조가 안 보인다.
"아이템을 버린다"는 기능이 계획됐다가 빠진 흔적일 수 있다.
재구성 시 버리기를 넣을 것인지 먼저 정하고, 안 넣으면 컴포넌트도 만들지 않는다.

### 8. `Death`가 카메라 두 개를 켜고 끈다

`Detach From Component`(Keep World 3종 + Call Modify) 후
`Set Active`로 `DeathCam`으로 전환한다. 전환이 즉각적이다(스냅).
MCP1의 `다음으로 넘김`에 있는 "전환 스냅 완화 — `SetViewTargetWithBlend`"와
같은 주제다. 원본도 같은 자리에서 같은 선택을 했다.
