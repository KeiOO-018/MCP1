# 04 · 적 AI와 전투

## 자료에 있는 것

### 클래스 구성

- `BP_ICI_SkeletonBase` — 부모
- `BP_ICI_Skeleton`, `BP_ICI_Skeleton2`, `BP_ICI_Skeleton3` — **자식 3종**
  - 자료 설명: "Skeleton마다 공격 데미지가 다름"
  - 스테이지별로 다른 종류가 배치된다 (`Drop Key`가 스테이지 2에서
    `BP_ICI_Skeleton 2`를 찾는다)
- `BP_ICI_MonsterController` — AI 컨트롤러
- `AnimBP_ICI_Skeleton` — 애님 블루프린트
- `BB_ICI_Monster_Blackboard`, BehaviorTree

### `BP_ICI_Skeleton` 구성

- 컴포넌트: `CapsuleComponent` → `Mesh(CharacterMesh0)` → `Widget`,
  `SkeletonCollision`, `StaticMesh` → `SwordCollision`, `Arrow`
- 메시 트랜스폼: 위치 Z **-79.0**, 회전 Z **-90.0**, 스케일 **3.0**
  (캡슐 스케일은 1.0 — 즉 **메시만 3배**로 키웠고 캡슐은 그대로다)
- `Max HP` **100.0**
- 애니메이션 모드 `Use Animation Blueprint`, 애님 클래스 `AnimBP_ICI_Skel…`
- 함수 35개 오버라이드 가능

변수:

| 변수 | 타입 |
|---|---|
| `HitActorsDuringSwing` | Actor 배열 |
| `IsDead` | Boolean |
| `IsHitKeyName` | Name |
| `IsDeadKeyName` | Name |
| `WBP Enemy Health` | WBP Enemy Health |
| `BO Other Actor` | Actor |
| `ICI Game Mode` | ICI Game Mode |
| `Stage1LastEnemyTransform` | Transform |

### BeginPlay

```
Sequence
  Then 0 : Get User Widget Object(Widget) → Cast To WBP_EnemyHealth
           → Set WBP Enemy Health
           → Set Current Health → Set Max Health
  Then 1 : Get Game Mode → Cast To ICI_GameMode → Set ICI Game Mode
```

### 피격 (`Event AnyDamage`)

```
Sequence
  Then 0 : Set Current HP = Clamp(Current HP - Damage, 0.0, Max HP)
           → Branch(Current HP <= 0.0)  → 사망 처리
  Then 1 : Set Current Health = Current Health - (Damage × 1.0)
           → WBP Enemy Health.Update Health
```

**체력이 두 벌이다** — `Current HP`(로직용)와 `Current Health`(위젯용)를 따로 계산한다.

사망 처리:

```
Get Blackboard → Set Value as Bool(Is Hit Key Name, true)
  → Branch
  → Set Value as Bool(Is Dead Key Name, Is Dead)
  → Set Is Dead = true
  → Get Anim Instance(Mesh) → Cast To AnimBP_ICI_Skeleton → Set Is Dead
  → Delay 4.0
  → Set Stage 1 Last Enemy Transform = Get Actor Transform(self)
  → Destroy Actor(self)
```

### 적의 공격

```
On Component Begin Overlap (SwordCollision)
  → Set BO Other Actor
  → Cast To ICI_Character
  → Branch(NOT (Hit Actors During Swing CONTAINS BO Other Actor))
  → Get Controller → Cast To BP_ICI_MonsterController
  → Apply Damage(Damaged Actor: 플레이어, Base Damage 10.0,
                 Event Instigator: 컨트롤러, Damage Causer: Self)
  → ADD(Hit Actors During Swing, BO Other Actor)
```

### AnimBP

`Event Blueprint Update Animation`:

```
Sequence
  Then 0 : Try Get Pawn Owner → Cast To BP_ICI_SkeletonBase
           → Set Speed = FInterp To(Speed,
                                    Vector Length(Get Velocity),
                                    Get World Delta Seconds,
                                    Interp Speed 5.0)
  Then 1 : Get Controller → IsValid → Cast To BP_ICI_MonsterController
           → Get Blackboard → Get Value as Bool("Is Attack")
           → Set Is Attacking
```

`FInterp To`로 속도를 보간하는 이유는 자료에 적혀 있다 —
"캐릭터가 갑자기 멈추거나 움직일 때 애니메이션이 자연스럽게 정지 상태에서
달리는 상태로 또는 Idle 전환".

### AnimNotify — 무기 콜리전 on/off

`AnimNotify_StartAttack`:

```
Sequence
  Then 0 : Cast To BP_ICI_Skeleton  → CLEAR(SwordCollision, HitActorsDuringSwing)
                                    → Set Collision Enabled(Query Only)
  Then 1 : Cast To BP_ICI_Skeleton2 → 동일
  Then 2 : Cast To BP_ICI_Skeleton3 → 동일
```

`AnimNotify_EndAttack`도 같은 3갈래로 `Set Collision Enabled(No Collision)`.

**하나의 AnimNotify가 자식 클래스 3개를 각각 캐스팅해 같은 일을 세 번 적는다.**

`AnimNotify_ResetAttack`:

```
Try Get Pawn Owner → Get Controller → Cast To BP_ICI_MonsterController
  → Get Blackboard → Set Value as Bool("Is Attack", false)
```

### BehaviorTree

```
ROOT (BB_ICI_Monster_Blackboard)
└ Selector
  ├ Selector
  │ └ [IsHit?  (Blackboard: IsHit is Set)]
  │   └ HitReaction (Sequence)
  │     └ BTTask_PlayHitReaction
  └ [Can See Player?  (aborts lower priority,
                       Blackboard: PlayerCharacter is Set)]
    └ Attack Player (Sequence)
      ├ Move To            (MoveTo: PlayerCharacter)
      ├ Rotate to face BB entry (RotateToFaceBBEntry: PlayerCharacter)
      ├ DamagePlayer       (BTTask_DoAttack, Target Actor Key: PlayerCharacter)
      └ Wait               (3.5 ± 0.5s)
```

`BTTask_PlayHitReaction`:

```
Event Receive Execute AI → Cast To BP_ICI_SkeletonBase → Finish Execute(Success ✔)
```

**캐스트만 하고 아무 동작도 없다. 빈 Task다.** 자료 본문도 그렇게 적었다.

`BTTask_DoAttack`:

```
Event Receive Execute AI
  → Get Player Character → Cast To ICI_Character → Is Dead
  → Branch
      True  : Finish Execute(Success ✔)
      False : Get Blackboard → Set Value as Bool("Is Attacking", true)
              → Finish Execute(Success ✔)
```

### 확인된 어긋남 — 블랙보드 키 이름이 두 가지다

- `AnimBP`는 `Is Attack`을 **읽는다**
- `AnimNotify_ResetAttack`은 `Is Attack`을 **false로 쓴다**
- `BTTask_DoAttack`은 **`Is Attacking`** 을 true로 **쓴다**

세 그래프가 같은 상태를 가리키는 것처럼 보이지만 이름이 다르다.
스크린샷의 변수 핀 이름 기준이며, 블랙보드에 두 키가 다 있는지는 **확인 안 됨.**

## 다시 만들면 (내 의견)

### 1. Skeleton 3종이 클래스 상속으로 갈라져 있다

데미지만 다른데 클래스가 셋이다. 그 결과가 AnimNotify의 3갈래 복붙이고,
`Drop Key`가 스테이지별로 다른 클래스를 `Get Actor Of Class`로 찾는 코드다.
**넷째가 생기면 AnimNotify를 또 고쳐야 한다.**

`BP_ICI_SkeletonBase` 하나만 두고 데미지·체력·이동속도를 인스턴스 편집 변수나
DataTable 행으로 뺀다. AnimNotify는 부모로만 캐스팅하면 3갈래가 1갈래가 된다.
**사다리 2번(이미 있는가)과 6번(정당화되는 만큼만)의 문제다.**

### 2. 체력이 두 벌이다

`Current HP`와 `Current Health`가 각각 계산되고, 위젯 갱신은 후자만 쓴다.
둘이 어긋나면 체력바와 실제 사망 시점이 달라진다.
**하나로 합치고 위젯은 그 값을 구독하게 한다.**

### 3. `BTTask_PlayHitReaction`이 빈 Task다

`IsHit` 블랙보드 키가 셋업돼 있고 트리 가지도 있는데 실행되는 내용이 없다.
**피격 리액션이 미구현인 채로 발표까지 갔다.**
재구성 시 두 갈래 중 하나 —
① 몽타주를 실제로 재생하고 끝날 때 `Finish Execute`,
② 필요 없다고 판단되면 가지를 지운다. **지우는 것도 유효한 답이다.**

### 4. `Wait 3.5 ± 0.5s`가 공격 쿨다운을 대신한다

공격 후 3.5초 대기가 트리에 박혀 있다. 적 종류마다 공격 속도를 다르게 하려면
트리를 복제해야 한다. 블랙보드 float 키로 빼거나 데이터로 옮긴다.
**단, 3.5라는 값 자체는 손으로 맞춘 값이므로 유지한다.**

### 5. 블랙보드 키 이름 불일치

`Is Attack` / `Is Attacking`. 블루프린트에서 블랙보드 키는 `Name`이라
**틀려도 컴파일 에러가 안 난다.** 조용히 항상 false를 읽는다.
재구성 시 키 이름을 하나로 통일하고, 가능하면 Blackboard Key Selector로 노출해
드롭다운에서 고르게 한다 — 오타가 불가능해진다.

이건 원본에서 **애님이 공격 상태를 못 읽고 있었을 가능성**을 뜻한다.
5.8에서 다시 만들 때 재현해서 확인할 가치가 있다.

### 6. 캡슐은 1.0인데 메시만 스케일 3.0

메시가 3배인데 콜리전 캡슐은 기본 크기다. 근접 판정과 보이는 몸집이 어긋난다.
`SkeletonCollision`, `SwordCollision`이 따로 있어 데미지 판정은 그쪽에서 나지만,
**이동·네비게이션·밀림은 캡슐 기준**이라 큰 해골이 좁은 문을 통과하거나
벽에 파묻히는 그림이 나온다.
재구성 시 캡슐을 메시에 맞추거나, 메시 스케일을 1로 되돌리고 애초에 큰 메시를 쓴다.

### 7. `Delay 4.0` 후 `Destroy Actor`

시체가 4초 뒤 사라진다. 그런데 `Count Enemy`는 `On Destroyed` 바인딩으로 돈다
([05-진행구조.md](05-진행구조.md)) — **즉 적이 죽고 나서 4초 뒤에야 카운트가 줄어든다.**
마지막 적을 죽여도 4초간 문이 안 열리고 HUD 숫자도 안 줄어든다.

이게 원본의 체감 문제였을 가능성이 높다. 재구성 시
**"죽음"과 "액터 파괴"를 분리한다** — 사망 시점에 즉시 카운트를 줄이고,
액터 정리는 별개로 미룬다.

### 8. `Apply Damage`의 Base Damage 10.0이 그래프에 상수로 박혀 있다

"Skeleton마다 공격 데미지가 다름"이라고 적혀 있는데 그래프에는 10.0이 리터럴이다.
자식 클래스에서 그래프를 덮어썼거나, 설명과 실제가 다르거나 둘 중 하나다.
**확인 안 됨.** 재구성 시 변수로 뺀다.
