# 05 · 진행 구조 — GameMode / GameState

원본에서 가장 덩치가 큰 부분이고, **가장 하드코딩이 심한 부분이다.**

## 자료에 있는 것

### `ICI_GameState`가 들고 있는 것

자료 설명: "Game State는 Game Mode 에서 진행하는 함수에 대해 값이 고유하거나
그 정보가 변하지 않는 중요한 판단 요소가 되는 것들을 저장하고 이를 가져와 쓰는 용도로
제작되어야 한다."

| 변수 | 용도 |
|---|---|
| `Current Stage` | int. 현재 스테이지 (1~3, 클리어 시 4) |
| `Current Enemy` | int. 이번 스테이지에 소환된 적 총수 |
| `Remain Enemy` | int. 남은 적 |
| `Current Stage Name` | Name. 스폰 포인트 태그로 쓰임 (`Stage1` 등) |
| `Is Stage 1 Clear?` / `2` / `3` | bool 3개 |
| `Start Stage` | bool. 스테이지 진행 중 여부 |
| `Is Player Dead` | bool |

### `ICI_GameMode`의 함수들

`Stage 1 Spawn` / `Stage 2 Spawn` / `Stage 3 Spawn`, `End Stage`,
`Add Current Stage`, `Count Enemy`, `Drop Key`, `Reset Current Stage`,
`Re Spawn`, `IsStageClear?`, 커스텀 이벤트 `Stage1` / `Stage2` / `Stage3`, `Count2`

### `Stage N Spawn`

```
Branch(GameState.Current Stage == N)
    False : Print String  ErrorCode("Stage 1 Spawn NULL")   Duration 10.0
    True  : Set Current Stage Name = "Stage1"
            → Get All Actors Of Class With Tag(ICI Spawn Point, Tag = Current Stage Name)
            → Set Spawn Point 1 (배열)
            → For Each Loop
                 → Get Actor Transform(Array Element)
                 → SpawnActor BP ICI Skeleton
                 → Print String "Stage 1 Spawn"
                 → GameState.Current Enemy + 1 → Set
              Completed
                 → Print String "Hello"
                 → Set Remain Enemy = Current Enemy
```

- 스폰 포인트를 **레벨 태그**로 찾는다. 레벨에 `ICI Spawn Point`를 놓고
  `Stage1` 같은 태그를 붙이는 방식
- `Print String`이 **3개** 남아 있다 (`"Stage 1 Spawn"`, `"Hello"`, ErrorCode)

### 스테이지 시작 (`Stage2` 커스텀 이벤트 예)

자료 코멘트: "Stage2 몬스터 소환 및 각 몬스터에 Count 이벤트 바인딩"

```
Stage2 (Custom Event)
  → Stage 2 Spawn(GameState)
  → Close Door(Stage 2Door) → Lock Door(Stage 2Door)
  → Get All Actors Of Class(BP_ICI_Skeleton 2)
  → For Each Loop
       → Bind Event to On Destroyed(Array Element, Event = Count2)
       → Print String "Bind"
    Completed → …

Count2 (Custom Event, Destroyed Actor)
  → Count Enemy(GameState)
  → Print String
  → Is Stage Clear?(self)
```

자료 설명: "Stage 시작 로직 작동은 Trigger Box 에 Player 가 Overlap 되었을 때 실행,
해당 Trigger Box 는 소멸한다."

### `Count Enemy`

```
GameState.Remain Enemy - 1 → Set Remain Enemy → Drop Key(self) → Return
```

### `Drop Key`

```
Branch(Remain Enemy == 0)
  → Switch on Int(Current Stage)
      1 : Get Actor Of Class(BP ICI Skeleton)   → Get Actor Transform → SpawnActor ICI Stage 2 Key
      2 : Get Actor Of Class(BP ICI Skeleton 2) → Get Actor Transform → SpawnActor ICI Stage 3 Key
```

([02-아이템-인벤토리.md](02-아이템-인벤토리.md)에 이 그래프와 자료 설명의 어긋남을 적었다)

### `IsStageClear?`

자료 코멘트: "스테이지 클리어 판단 유무 -> 적 AI가 트리거"

```
Branch( (Remain Enemy == 0) AND (NOT Is Player Dead) )
  → Switch on Int(Current Stage)
      1 : Set Is Stage 1 Clear? = true
      2 : Set Is Stage 2 Clear? = true
      3 : Set Is Stage 3 Clear? = true
  → Un Lock Door(Stage N Door) → Open Door(Stage N Door)   ← 스테이지별 3벌
  → Add Current Stage(self)
  → Set Start Stage = false
  → Set Current Enemy = 0
  → End Stage(self)
```

### `Add Current Stage`

```
Set Current Stage = Current Stage + 1
```

### `Reset Current Stage` — 플레이어 사망 시

```
Switch on Int(Current Stage)
  각 가지(1/2/3)마다:
    Branch(Is Stage N Clear?)
      → Un Lock Door(Stage N Door) → Open Door(Stage N Door)
      → Get All Actors Of Class(BP_ICI_Skeleton) → For Each → Destroy Actor
      → SpawnActor ICI Trigger Box Stage N  (Spawn Transform = "Trigger Box N")
      → IsValid(ICI_StageN_Key)
           → Get Actor Of Class(ICI Stage N Key) → Destroy Actor
      → Set Current Enemy = 0 → Set Remain Enemy = 0
```

자료 표기: "위 과정이 Current Stage의 Switch On Int 정보에 따라 **1부터 3까지 모두 있음**"

### `Re Spawn`

자료에 두 가지 버전의 스크린샷이 있다.

버전 A (p.28):

```
Get Player Controller → Find Player Start → Get Actor Transform → Break Transform
  → SpawnActor ICI Character(Location / Rotation / Scale 그대로)
  → Get Player Controller → Possess
  → IsValid → Cast To ICI_Character → Get Player Character → Set Player REF
```

버전 B (p.42, `Respawn` 코멘트):

```
… Break Transform → Break Vector → (Z + 130.0) → Make Vector
  → SpawnActor ICI Character
       Spawn Transform Rotation 0,0,0
       Spawn Transform Scale 1,1,1
  → Possess → IsValid → Cast → Set Player REF
```

**B는 Z를 130 올려서 스폰한다.** 바닥에 파묻히는 것을 피하려는 값으로 보이며,
플레이어의 `BeginLanding`(부드러운 착지)과 짝을 이룬다
([06-플레이어-UI.md](06-플레이어-UI.md)).

### `End Stage`

자료 설명: "스테이지를 조건에 맞게 클리어 했을 때, 플레이어의 상태 회복하는 함수"
(그래프 스크린샷은 자료에 없다 — **확인 안 됨**)

## 다시 만들면 (내 의견)

### 1. 스테이지 3개가 코드에 3벌로 복사돼 있다

`Stage 1/2/3 Spawn`이 함수 3개, `Stage1/2/3` 커스텀 이벤트가 3개,
`IsStageClear?`의 `Switch on Int`가 3가지, `Reset Current Stage`가 3벌,
`Is Stage N Clear?` bool이 3개, `Stage N Door` 변수가 3개.

**스테이지 하나를 늘리면 GameMode에서 최소 6군데를 고쳐야 한다.**

원본이 스스로 적어둔 문장이 증거다 —
"위 과정이 Current Stage의 Switch On Int 정보에 따라 1부터 3까지 모두 있음."

**재설계 방향:** 스테이지를 데이터로 만든다.

- `Is Stage N Clear?` bool 3개 → **bool 배열** 또는 `Set<int>`
- `Stage N Door` 변수 3개 → **문 배열**, 또는 각 문이 자기 스테이지 번호를 안다
- `Stage N Spawn` 함수 3개 → **`SpawnStage(int N)` 하나.**
  태그는 이미 `Current Stage Name`으로 문자열 조립 가능하다
  (원본도 `Set Current Stage Name`을 하고 있다 — 절반은 이미 데이터 주도다)
- 스테이지 구성(적 수·종류·열쇠 클래스)이 늘어나면 그때 DataTable로 뺀다

### 2. `On Destroyed` 바인딩이 카운트의 유일한 경로다

적 사망 → `Delay 4.0` → `Destroy Actor` → `On Destroyed` → `Count Enemy`.
**죽고 4초 뒤에 카운트가 준다.**
([04-적AI-전투.md](04-적AI-전투.md) 7번 참조)

재구성 시 적이 사망 시점에 **이벤트 디스패처**로 알리고, GameMode가 그걸 구독한다.
액터 파괴는 연출용으로 남긴다.

### 3. `Get All Actors Of Class`가 여기저기서 돌아간다

`Stage N` 이벤트에서 한 번(바인딩용), `Reset Current Stage`에서 한 번(정리용),
`Drop Key`에서 `Get Actor Of Class` 한 번. 스폰한 적을 **배열로 들고 있으면**
전부 없어진다. `Stage N Spawn`이 이미 `For Each`로 스폰하고 있으니
그 자리에서 배열에 담으면 된다.

(Tick에서 도는 건 아니라 성능 문제는 아니다. 문제는
**"방금 내가 스폰한 것"을 다시 찾는다는 구조 자체**다.
레벨에 다른 스켈레톤이 놓여 있으면 조용히 같이 잡힌다)

### 4. `Print String`이 최소 5개 남아 있다

`"Stage 1 Spawn"`, `"Hello"`, `"Bind"`, ErrorCode 문자열, `Count2` 안의 것.
발표 자료 스크린샷에 그대로 찍혀 있다.
**재구성 시 로깅이 필요하면 `Print String`이 아니라 `Print Text` + 개발 전용 분기,
또는 그냥 지운다.**

### 5. 리스폰이 새 캐릭터를 스폰하고 기존 것을 파괴한다

플레이어의 `Event AnyDamage` → `Death` → `Delay 7.0` → `GameMode.Re Spawn` →
`Destroy Actor(self)`. 새 폰이 생기고 `Player REF`를 다시 세팅한다.

**문제:** `Player REF`를 들고 있는 곳이 여럿이다 — `Stage2Door`의 `PlayerREF`,
`ICI_MasterItem`의 `Character REF`. 이들은 `IsValid` 실패 시 다시 잡는 방어 코드가
들어 있다. **즉 "리스폰하면 참조가 끊긴다"는 걸 알고 각자 땜빵한 것이다.**

재구성 시 두 갈래:

- **A. 폰을 파괴하지 않는다** — 체력·상태를 되돌리고 위치만 옮긴다.
  참조가 끊기지 않으므로 방어 코드 전부가 사라진다. **이쪽을 권한다**
- **B. 파괴를 유지한다면** 참조를 캐시하지 않고 필요할 때
  `Get Player Character`로 가져온다

### 6. `Delay 7.0`이 사망 연출 길이와 리스폰 타이밍을 동시에 결정한다

`Start Camera Fade`의 Duration도 7.0이다. 두 값이 같아야 화면이 다 어두워진 뒤
리스폰되는데, 지금은 각각 따로 적힌 상수다. **한쪽만 고치면 어긋난다.**
변수 하나로 묶는다.

### 7. 남는 질문 — `End Stage`가 정확히 무엇을 하는가

"플레이어의 상태 회복"이라고만 적혀 있고 그래프가 없다.
HP만인지 SP도인지, 인벤토리는 어떻게 되는지 **확인 안 됨.**
재구성 시 이건 사양을 새로 정해야 한다.
