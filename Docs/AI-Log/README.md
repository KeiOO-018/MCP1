# AI 작업 기록 (AI-Log)

MCP 플러그인으로 언리얼을 조작한 작업을 **하나씩 차근차근 남기는** 기록입니다.
목적은 두 가지 — **나중에 내가 뭘 했는지 다시 확인하는 것**, 그리고 **포트폴리오로 쓰는 것**.

그래서 그 자리에 없던 사람이 읽어도 이해되게 씁니다.
"뭘 눌렀다"가 아니라 **"왜 그렇게 동작하는가"** 까지 적는 게 이 기록의 값입니다.

---

## 보는 법

이 파일들은 마크다운입니다. VS Code에서 파일을 열고 **`Ctrl+Shift+V`** 를 누르면
제목·표·코드가 웹페이지처럼 렌더링됩니다. 편집 화면의 `#`, `|` 기호는 원본에서만 보입니다.

GitHub에 올리면 웹에서 자동으로 렌더링되므로, 나중에 링크 하나로 공유할 수도 있습니다.

## 새 기록 만들기

`_template.md` 를 복사해서 `YYYY-MM-DD-작업이름.md` 로 저장하고, 위 세션 목록에 한 줄 추가합니다.

세션 중이라면 그냥 **"기록해줘"** 라고 하면 됩니다.
Claude가 `git status`로 변화점을 수집해 초안을 채워줍니다.

## 작업 규칙은 어디에?

세션 규칙(작업 전 커밋, 합격 기준 먼저 정하기, 명령 원문 보존 등)은
**프로젝트 루트의 [`CLAUDE.md`](../../CLAUDE.md)** 한 곳에만 적혀 있습니다.

그 파일은 이 프로젝트 폴더에서 Claude Code를 열 때 **자동으로 읽힙니다.**
규칙을 바꾸고 싶으면 거기만 고치면 됩니다. (여기에 중복해서 적지 마세요 — 나중에 어긋납니다.)

## 각 기록에 뭐가 들어 있나

| 장 | 내용 | 나중에 이걸 볼 때 |
|---|---|---|
| 1 | 메타 (날짜·엔진·소요 시간·커밋 해시) | 언제 뭘 했는지 |
| 2 | **내가 내린 명령 원문** | AI에게 어떻게 지시했는지 — 다듬지 않고 그대로 |
| 3 | 변화점 (`git status` + 무엇이 왜 그 값인지) | 정확히 뭐가 바뀌었는지 |
| 4 | **왜 이게 동작하는가** | 복기할 때 여기만 읽으면 됨 |
| 5 | 이번 작업에 쓰인 엔진 지식 | 한 줄씩 훑어 기억을 되살릴 때 |
| 6 | 검증 범위 — **확인 못 한 것 포함** | 어디까지 믿을 수 있는지 |
| 7 | 설계 판단과 대안 | 왜 다른 길을 안 갔는지 |
| 8 | 재현 난이도 | 다시 만들 때 어디가 함정인지 |
| 9 | 인수인계 | 다음 세션이 이어받을 것 |

**AI가 전부 채웁니다.** 빈칸을 남기지 않습니다 — 미완성 기록은 나중에 읽을 수 없으니까요.
딱 하나, **7장의 "내 결정" 칸**만 비어 있습니다. 대안 쪽으로 갈 생각이 생기면 거기 적으세요.

포트폴리오로 낼 때 값이 나가는 건 **4장 · 6장 "확인 못 한 것" · 7장** 입니다.
동작시킨 것보다 **왜 그렇게 되는지 알고 있고, 어디까지 확인했는지 정직하게 적는 쪽**이 드뭅니다.

## 세션 사이를 잇는 법 (9장 인수인계)

각 기록의 **9장**에는 그 세션이 다 못 끝낸 것 — 미룬 개선, 확인 못 한 것,
결정이 필요한 것 — 이 적힙니다. 기록이 과거형 스냅샷이라면, 9장만 **미래형**입니다.

이게 자동으로 이어지는 구조는 이렇습니다.

```
세션 종료 → 기록 9장에 미결 항목을 적는다        (CLAUDE.md 규칙 3)
                        ↓
세션 시작 → 가장 최근 기록의 9장을 읽고 짚어준다   (CLAUDE.md 규칙 0)
                        ↓
            처리한 항목은 9장에서 지운다
```

`CLAUDE.md`는 이 폴더에서 Claude Code를 열 때 자동으로 읽히므로,
**따로 말하지 않아도 다음 세션이 9장부터 봅니다.** 처리한 줄을 지우는 것만 잊지 마세요.
