## 4. 구현 분석 — 왜 이게 동작하는가

### (1) `templates/`는 왜 지금까지 아무 효과가 없었는가

Claude Code가 자동으로 읽는 위치는 정해져 있다 — 프로젝트 루트의 `CLAUDE.md`,
그리고 `~/.claude/CLAUDE.md`(전역)다. `~/.claude/commands/*.md`는 슬래시 커맨드가 된다.

`~/.claude/templates/`는 **그 어느 목록에도 없다.** 확인 결과:

- `~/.claude/commands/` 폴더 자체가 존재하지 않음
- `~/.claude/CLAUDE.md` 파일이 존재하지 않음

그래서 `new-object.md`가 슬래시 커맨드 포맷(`description` / `argument-hint` 프론트매터 +
`$ARGUMENTS`)으로 **정확히 쓰여 있는데도** `/new-object`는 존재한 적이 없다.
포맷이 아니라 **위치**가 활성/비활성을 가른다. `templates/`는 수동 복사용 선반이다.

### (2) 그래서 이번 작업의 실체는 "복사"가 아니라 "활성화"

내용을 옮겼기 때문에 효과가 생기는 게 아니라,
**자동으로 읽히는 경로에 놓았기 때문에** 효과가 생긴다.
같은 문장이 `templates/`에 있으면 0, `CLAUDE.md`에 있으면 1이다.

### (3) 이번 세션에는 적용되지 않는다

`CLAUDE.md`는 **세션 시작 시점에 한 번** 읽힌다. 지금 이 세션은 병합 이전 내용으로 돌고 있다.
새 규칙이 실제로 작동하는지는 **다음 세션에서만** 확인할 수 있다. (→ 6장)

### (4) C++ 조항을 왜 통째로 버리지 않고 골라냈는가

`unreal-CLAUDE.md`에는 두 종류가 섞여 있었다.

- **C++ 문법 조항** — `UPROPERTY` 없으면 GC된다, `.generated.h`는 마지막 include다.
  BP에는 대응물이 없다. 버림
- **엔진 동작 조항** — 틱 예산, 리플리케이션 계약, 기본값 직렬화, 참조 끊김.
  **언어와 무관하게 엔진이 그렇게 동작한다.** BP에서도 그대로 성립한다. 옮김

둘이 한 덩어리로 붙어 있어서 지금까지 BP 프로젝트로 넘어오지 못했다.

### (5) 옮기면서 문법을 바꾼 항목

원본의 C++ 표현을 BP 표현으로 번역한 것이 둘 있다.

| 원본 (C++) | 옮긴 형태 (BP) |
|---|---|
| C++ 기본값을 바꿔도 이미 직렬화한 BP·배치 액터는 갱신되지 않는다 | 부모 BP 기본값을 바꿔도 오버라이드한 자식 BP·배치 인스턴스는 따라오지 않는다 |
| `UPROPERTY(Replicated)` 와 `DOREPLIFETIME` 둘 다 필요 — 하나만 하면 조용한 버그 | `Replicated`를 켰으면 `RepNotify`가 필요한지 함께 판단 — 값 반영에 반응이 따라와야 하면 부족 |

`DOREPLIFETIME`은 BP에 대응물이 없어 그대로 옮길 수 없었다.
원본 조항의 **취지**(리플리케이트 선언만으로는 절반이다)를 BP에서 같은 함정인
`RepNotify` 누락으로 대체했다.

| BP 리네임의 위험 | BP 변수·함수·이벤트 디스패처 이름을 바꾸면 참조하던 다른 BP·레벨 BP·애님 BP가 **컴파일 에러 없이** 끊길 수 있다 |

| `Text` vs `String` | `Text` → `String` 다운그레이드는 로컬라이제이션을 버리는 일이다 |
| 규칙 문서의 분해 기준 | 언리얼 규칙에는 **C++ 문법 조항**과 **엔진 동작 조항**이 섞여 있다. 후자는 언어와 무관하게 성립하므로 BP 프로젝트로 넘어올 수 있다. 이 구분이 이번 작업 전체의 기준이 됐다 |

| 애셋 6건을 **같은 커밋에 담지 않음** | 함께 커밋 | 분리 = 문서 이력이 깨끗함 / 함께 = 커밋 수가 줄어듦 | 문서 규칙 변경과 카메라 작업 결과물은 성격이 다르다. 나중에 이력을 되짚을 때 섞여 있으면 못 읽는다 | |
| 인수인계를 **9장 + 규칙 0**으로 구현 | 별도 TODO 문서 | 9장 = 기록과 같은 파일이라 맥락이 붙어 있음 / 별도 문서 = 한눈에 보이지만 기록과 따로 놀고 갱신을 잊는다 | 자동 로드되는 `CLAUDE.md`가 가리킬 수 있으면 사용자가 매번 말하지 않아도 이어진다 | |

### 알아둘 잠재 이슈

- `templates/` → `CLAUDE.md` 는 **한 방향 복사이고 역류가 없다.** 이 프로젝트에서 얻은 개선
  (MCP 예외 조항, 세션 규칙 3개, 5장 체크 방식)이 원본으로 돌아가지 않으므로,
  다음 프로젝트는 다시 MCP 이전 버전의 `unreal-CLAUDE.md`에서 시작하게 된다
- `Docs/AI-Log/_template.md`가 **실사용을 못 따라가고 있다.** 카메라 로그에서 진화한 형태
  (5장 = AI가 항목을 쓰고 사용자가 체크 / 7장 하위 절 2개 / "다음에 시도해볼 작업")가
  템플릿에 반영되지 않았다. 이 문서도 템플릿이 아니라 카메라 로그를 보고 썼다
- `README.md` 세션 목록의 "혼자 가능?"이 기록 2건 모두 미결이다.
  8장을 안 채우면 이 칸이 경고등 역할을 못 한다

## 8. 재현 난이도 — 다시 만든다면 어디가 까다로운가

| 단계 | 난이도 | 까다로운 지점 |
|---|---|---|
| 자동 로드 경로 확인 (`commands/`, `~/.claude/CLAUDE.md` 부재) | 쉬움 | `ls` 두 번. 다만 **확인할 생각을 하는 것**이 핵심이다. 안 하면 "규칙을 깔아뒀다"고 착각한 채로 계속 간다 |
| C++ 조항과 엔진 조항 **구분** | **함정** | 원본에 둘이 한 덩어리로 섞여 있다. 기준 없이 읽으면 "C++ 문서니까 BP엔 무관"으로 통째 버리게 되고, 실제로 지금까지 그래 왔다. **이 작업의 실질적 난이도가 여기 있다** |
| C++ 조항을 BP 대응으로 번역 | **함정** | `DOREPLIFETIME`처럼 BP에 대응물이 없는 경우, 문구가 아니라 **취지**("선언만으론 절반이다")를 옮겨야 한다. 직역하면 쓸모없는 줄이 된다 |
| 규칙을 CLAUDE.md에 병합 | 쉬움 | 텍스트 편집. 단 기존 규칙이 유실되지 않았는지 diff의 삭제 줄만 뽑아 대조해야 한다 |
| 인수인계 고리 설계 | 보통 | "9장에 쓴다"만으로는 안 이어진다. **자동 로드되는 문서가 그걸 가리켜야** 비로소 순환이 닫힌다 |
| `unreal-CLAUDE.md` 공통/C++ 분리 | 보통 | 위의 구분 기준이 서 있으면 기계적인 작업. 아직 안 했다 (9장) |

**이 작업의 핵심 한 줄:**
규칙 문서의 효력은 **내용이 아니라 위치**가 결정한다. 같은 문장이 `templates/`에 있으면 0이고
`CLAUDE.md`에 있으면 1이다. 그래서 이 작업의 실체는 "복사"가 아니라 "활성화"였다.

- [ ] `~/.claude/CLAUDE.md`(전역)와 프로젝트 `CLAUDE.md`가 함께 로드될 때 어떻게 합쳐지는지 확인
