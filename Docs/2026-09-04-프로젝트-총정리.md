# 1 · 무엇을 만들었나

## 1.1 레벨 — `Lvl_Stage`

원본 발표자료 `p.16` 평면도를 판독해 옮긴 **T자 구조**다. 축은 `+X = 북`, `+Y = 동`.
World Partition + One File Per Actor이고, 디스크에 액터 패키지 **113개**가 있다.

```
                        ┌──────────────┐
                        │    방 2      │   X +1300..+2900
                        │   10 × 8칸   │
                        └──────┬───────┘
                          Door_R2 (은열쇠)
┌──────────────┐    ┌──────────┴───────┐    ┌──────────────┐
│    방 1      ├────┤      로비        ├────┤    방 3      │
│    9 × 8칸   │ R1 │    14 × 11칸     │ R3 │   10 × 8칸   │
└──────────────┘    │  ∩자 2층 발코니  │    └──────────────┘
                    └──────────────────┘
```

| 요소 | 값 |
|---|---|
| 전체 외곽 | `Y -3600..+3800` × `X -1300..+3100` (`37 × 22`칸, 1칸 = `200`) |
| 벽 | 하단 `Z 0..200` · 상단 `Z 200..400`, 두께 `200`. 2층 벽 `Z 400..1200` |
| 문간 | 폭 `200` × 높이 **`400`** (09-03에 `200`에서 올림). 인방은 위 벽이 겸한다 |
| 2층 | `∩`자 발코니. 걷는 면 `Z 600`, 램프 2개(경사 `31.0°`)로 오른다 |
| 최종 구역 | 2층 북쪽 문 너머 복도 + 막다른 방. 방2 천장 위 허공에 떠 있다 |
| 천장 | 로비만 있다 (`Z 1200..1250`). 방 셋과 최종 구역은 뚫려 있다 |
| 기둥 | 6개 (`SM_Cylinder`, `Z 0..550`) |
| NavMesh | `NavBounds_Main` — `Z -200..350`. **1층만 덮는다.** 2층·램프·최종 구역은 없다 |

**지오메트리는 전부 `SM_Cube` · `SM_Ramp` · `SM_Cylinder`를 늘린 것이다.**
타일 모듈이 아니라 구간 하나를 큐브 하나로 덮는 방식이다. 원본도 결국 직육면체로
끝났으므로 (`08-레벨-평면도.md`) 이 지점이 원본과 같은 자리다.

`Lvl_ThirdPerson`(액터 43개)은 08-31까지 쓰던 두 방짜리 이전 레벨이고 09-03에
`Lvl_Stage`로 갈아탄 뒤로 안 쓴다. **지우지 않고 남겨뒀다.**

## 1.2 시스템별 현황

### 인벤토리 — 원본을 넘어섰다

- `S_ItemDef` 구조체 + `E_ItemNature` 열거형(`Key` / `Consumable` / `Holdable`)
  + `DT_Items` DataTable **6행**(`Key_Stage1/2/3` · `Potion_Small` · `Knife` · `Ball_Test`)
- 슬롯 **3칸**. 개수는 `BP_ThirdPersonHUD.SlotCount` 변수 하나가 정한다
- `1`/`2`/`3` 키 선택 — Enhanced Input의 **Scalar 모디파이어 하나로 액션 1개**가 세 값을 나른다
- 선택 = 장착. 선택된 칸의 `Holdable`이 오른손 소켓에 자동으로 붙는다 (`RefreshHeldItem`)
- `E` 사용 (`TryConsumeSelected`) · `Q` 버리기(바닥 라인트레이스 후 스폰) · `F` 습득
- HUD는 **UMG 위젯을 하나도 안 만들고** `AHUD`의 `DrawRect`/`DrawText` 캔버스로 그린다

원본은 아이템이 **열쇠 하나뿐**이었고 슬롯 2칸을 `Switch on Int` 0/1로 하드코딩했으며
아이템을 `Item_Name` 문자열 비교로 식별했다. 그 셋이 전부 데이터로 내려갔다.

### 상호작용과 문 — 완료

- `BPI_Interact` 인터페이스 하나. **함수 이름이 `Interact`** — 대상 이름이 안 박혀 있다
- 상호작용 경로가 **하나뿐**이다. 문도 아이템도 같은 라인트레이스(`InteractDistance`)를 탄다
- `BP_Door` 상태 셋 — `bLocked`(열쇠 필요) · `bOpen`(열림) · `bSealed`(전투 중 봉인).
  뜻이 셋 다 다르다
- `RequiredKey`가 인스턴스 변수라 **문 클래스가 하나**다. 원본은 `Stage2Door`처럼
  문마다 전용 클래스였다
- 문 4개 — `Door_R1`(안 잠김) · `Door_R2`(은열쇠) · `Door_R3`(동열쇠) ·
  `Door_Final`(`ClearedRooms == 3`에 열림, 태그 `FinalDoor`)

### 적 AI — BehaviorTree를 안 쓴 대체 구현

`BP_Enemy` **한 클래스**, 변수 21개. `EventGraph`의 자기호출 `Think` 루프로 돈다.

| 기능 | 값의 주인 |
|---|---|
| 시야 | `SightRange` · `SightHalfAngle` + 라인 오브 사이트 (벽 너머 감지 차단) |
| 추격 | `ThinkInterval`마다 재평가 |
| 공격 | `AttackRange` · `AttackDamage` · `AttackCooldown`, 때리기 전 플레이어 쪽으로 Yaw 회전 |
| 타격 판정 | AnimNotify로 창을 열고 **주먹 궤적 스윕 트레이스**(`FistRadius`, `HitActorsThisSwing`) |
| 복귀 | `ReturnDelay` · `ReturnSightRange` · `HomeLocation/Rotation` · `HomeArriveRadius` |
| HP | `MaxHP` / `CurrentHP` 한 벌 |
| 소속 | `OwningRoom` — 자기 방에 사망을 알린다 |

**시야각 · 복귀 · 방 소속은 원본에 없다.** 원본은 `Can See Player` 데코레이터뿐이라
한 번 본 플레이어를 영원히 쫓았다.

방마다 적 **2명**, 총 6명. 적끼리는 서로 때리지 않는다(09-02에 막음).

### 전투 — 판정은 원본보다 정확하고, 연출이 없다

- 플레이어: 칼(`Knife`)을 주워 들고 `LMB`로 휘두른다. `AM_Player_Attack` 몽타주의
  노티파이가 창을 열면 **매 프레임 이전 칼날 위치 → 현재 위치로 상자 스윕**
  (`BladeHalfLength` · `BladeRadius`), 한 스윙에 같은 적은 한 번만
- 공격 중 점프 금지(양방향), 플레이어만 상하체 분리(적은 전신 유지)
- 원본은 콜리전 컴포넌트 오버랩 + `Apply Damage`였다. **터널링에 강한 쪽으로 갔다**
- **없는 것** — 피격 리액션, 사망 몽타주, 적 체력바, 타격 이펙트·사운드

### 진행 구조 — `BP_StageRoom` 한 클래스

원본은 `Stage 1/2/3 Spawn` 함수 3벌 · `Is Stage N Clear?` bool 3개 ·
`Reset Current Stage` 3벌이었다. 그게 **클래스 하나 + 인스턴스 변수**가 됐다.

```
방에 들어감  → RoomBounds 오버랩 → bStageActive = true → 문 봉인(bSealed)
적 전멸      → NotifyEnemyDied → 봉인 해제 · 문 열림
                                 → KeyToDrop 스폰 (최종 방이면 안 함)
                                 → GameMode.NotifyRoomCleared → ClearedRooms += 1
ClearedRooms == 3 → "ALL STAGES CLEAR" → Door_Final 개방
막다른 방 진입    → BP_EndTrigger → "GAME CLEAR"
방 안에서 죽음    → NotifyPlayerDied → ResetRoom (그 방만 초기화)
```

`ResetRoom`은 `EnemySpawns` 배열에 담아둔 Transform으로 적을 다시 스폰한다.
원본처럼 `Get All Actors Of Class`로 재탐색하지 않는다.

### 플레이어와 HUD

- `V`로 3인칭 ↔ 1인칭 전환. 1인칭은 카메라를 `head` 본에 붙여 **자기 팔이 보인다**.
  피치 제한이 시점별로 따로 있다 (`FirstPersonPitchMin/Max` · `ThirdPersonPitchMin/Max`)
- HP `100`, 피격 · 사망 · `RespawnDelay` 후 리스폰
- HUD가 그리는 것 — 슬롯 3칸(선택 칸 초록 테두리) · HP 바 · 아이템 이름 ·
  `[E] Use` 프롬프트 · 좌상단 안내 메시지(`MessageDuration`으로 자동 소멸)
- **없는 것** — 스태미나와 달리기(원본 문서의 절반이 이 시스템이다), 사망 연출,
  스테이지 정보 UI, 아이템 아이콘 텍스처(지금은 `iconColor` 색상만)

그 다음 줄에 적 체력바 · 아이템 아이콘 텍스처 · 중복 열쇠 회수 ·

# 3 · 작업 방식 회고

08-29에 사흘치를 한 번 점검했고(`Docs/2026-08-29-중간점검.md`), 그 뒤 6일치가 더 쌓였다.
이 절은 9일 전체를 다시 본 것이다.

## 3.1 이 프로젝트의 작업 방식

```
심문 → 사양 → 명령 또는 구현 → 남의 눈 검증 → (기록)
```

- **AI는 명령문을 쓰고, 사람이 UE의 Terminal에 붙여넣어 실행한다.**
  AI가 MCP로 직접 조작하지 않는 것이 원칙이다
- **명령은 한 번에 하나.** 앞 결과를 보고 다음으로 간다
- **명령마다 보고서를 파일로 받는다** (`Docs/Terminal-Log/`)
- 구현 전에 **사양과 합격 기준**을 파일로 고정한다 (`Docs/Spec/`)

### 이 분업이 이겼다 — 명령문이 실행 전에 한 번 더 검토를 거친다

08-28 HUD 세션에서 AI가 역할을 벗어나 MCP로 50번 넘게 직접 호출했다. 사용자가 제동을
걸어서야 멈췄고, 그 사이 사용자는 화면에서 아무것도 못 봤다. 역할을 나눈 뒤로
**AI가 쓴 명령문의 오류를 터미널이 실행 전에 잡는 일**이 반복됐다.

- "미연결 이벤트 노드를 지우고 새로 추가하라" → 그 둘은 같은 노드였다
- "`DrawRect` 12개" → 실제로는 4개였다
- `IsValid`를 순수 함수 + `Branch`로 지시 → 매크로 자체가 분기다
- `GetTextSize`가 exec 핀을 가진다고 단정 → 실제로는 pure다
- 보고 파일을 `Saved/`에 쓰라고 지시 → `.gitignore`에 걸린다

**AI가 다 했으면 다섯 개 다 그대로 들어갔다.**

### 터미널 보고를 파일로 받는 것이 옳았다

화면 붙여넣기는 터미널 폭에서 잘리고, **잘린 조각이 원문 행세를 한다.**
08-29에 파일 방식으로 바꾸자 보완 호출이 5~10회에서 3회로 줄고 잘림이 사라졌다.

09-03에 그 실패가 원문으로 다시 잡혔다 — 붙여넣은 보고가 `"A third"` 한복판에서
잘렸고 터미널이 그것을 이렇게 짚었다.

```
Also worth naming: your message is a truncated fragment of my own previous
report — it stops mid-sentence at "A third".
```

### MCP 응답을 안 믿고 다시 읽는 습관이 값을 냈다

08-29 명령 15가 **실행되지 않았는데 명령 14의 결과가 다시 붙여졌다.**
디스크 크기 · mtime · 미연결 핀으로 잡았다. 붙여넣기만 믿었으면 없는 작업을
있다고 판단하고 다음 단계로 갔다.

### 버그를 로그로 잡았다

"가설 한 문장 → 이 가설이 틀렸다면 무엇이 보일지 → PIE 재현 → 그다음 수정" 절차가
실제로 작동했다. 고쳐보고 돌려보기를 반복한 세션이 없다.

## 3.3 UE 5.8 — 좋았던 것과 걸리는 것

**좋았던 것**

- **바이너리 설치본에 `Engine/Source`와 `Templates`가 통째로 들어 있다.**
  추측할 필요가 없다. `Variant_Shooter`를 새 프로젝트 만들어 Migrate하려던 계획을
  엔진 설치본을 먼저 뒤져서 없앴고 50분에 끝났다. 계획대로 했으면 충돌 19개를 손으로 처리했다
- **Enhanced Input의 Scalar 모디파이어** — 액션 하나로 `1`/`2`/`3`을 나른다
- **`AHUD::DrawRect` / `DrawText` 캔버스 경로** — UMG 위젯 계층을 하나도 안 만들고
  슬롯 UI · HP 바 · 아이템 이름 · 메시지를 전부 그렸다
- **`ConstructionScript` + DataTable RowName** — 디테일 패널에서 행을 고르는 순간
  뷰포트에 메시가 뜬다. 확인 비용이 크게 줄었다
- **World Partition + OFPA** — 액터마다 파일이 갈려서 git diff가 "무엇을 건드렸나"를 보여준다

**걸리는 것**

- **EventGraph에 로컬 변수가 없다.** 한 번 쓰고 버릴 값이 클래스 멤버로 남는다.
  **죽은 변수가 쌓이는 구조적 이유가 여기 있다**
- **승격 연산자를 재배선하면 안 건드린 리터럴이 조용히 지워진다.**
  `warnings_as_errors=true` 컴파일이 그대로 통과시킨다
- **`double` → `float` 축소 변환이 경고 없이 컴파일된다**
- **BP 변수·함수·이벤트 이름을 바꾸면 참조하던 다른 BP가 컴파일 에러 없이 조용히 끊긴다.**
  MCP로 대량 조작할 때 특히 위험하다
- **UE 로그는 UTC, 파일시스템·git은 KST.** 9시간 차를 매번 보정해야 했고
  날짜가 자정을 넘어가는 경우도 있었다
- 에디터가 09-03에 한 번 크래시했다 (애셋 삭제 중)

**판단 보류** — 5.4/5.5 대비 무엇이 나아졌는지는 비교 대상이 없어 말할 수 없다.

## 3.4 `unreal-mcp` — 한 줄로: 읽기는 쓸 만하고, 쓰기는 반환값을 믿을 수 없다

**반환값이 증거가 아니다.** 이게 핵심이고 9일 내내 유효했다.

- `add_variable` · `compile_blueprint`는 **성공에 `null`**
- `set_properties` · `save_assets`는 **`true`**. `save_assets`는 **하지 않은 쓰기도 `true`로 보고한다**
- `set_properties`가 CDO를 바꿔도 **컴파일 안 하면 런타임에 반영되지 않는다.**
  값을 읽으면 새 값이 나오는데 게임은 옛 값으로 돈다 — **읽기로는 절대 못 잡는 어긋남이다**
- **컴포넌트 스케일(`RelativeScale3D`)은 `set_properties`로 못 쓴다.** `true`를 주고 조용히 무시된다
- **MCP 컴파일은 이미 배치된 액터를 갱신하지 않는다.** 클래스 기본값을 바꿔도 배치
  인스턴스는 옛 값을 들고 있다. 레벨 리로드가 필요하다
- **PIE가 돌고 있으면 MCP가 PIE 세계를 읽는다.** `refPath`에 `UEDPIE_0_`이 붙고 액터 수가 다르다

**읽기의 사각지대**

- `read_graph_dsl`은 함수 그래프에서 정확하지만 EventGraph의 `EnhancedInputAction`
  체인에서 본체가 잘리고, 한 핀에 들어오는 두 번째 연결을 생략한다.
  **`read_graph_dsl → write_graph_dsl` 왕복은 체인을 조용히 지운다**
- **연결된 핀도 `value`에 옛 리터럴을 들고 있다.** `connected_pins`를 봐야 한다
- `get_properties`는 `..._C`가 아니라 `Default__..._C`(CDO)를 넘겨야 한다
- **BP 변수의 타입을 읽는 도구가 없다.** `get_node_type_pins`로 우회한다
- `get_variable_instance_editable`이 없다 — 디테일 패널을 눈으로 봐야 했다

**못 만드는 것** — enum과 구조체는 손으로만 만들 수 있고 편집도 안 된다.
배열에 원소를 덧붙이는 툴이 없다. Niagara 툴셋이 없다.

**판단** — 이 플러그인의 값은 "쓰기"가 아니라 **"읽기와 감사"**에 있었다.
블루프린트 그래프를 텍스트로 뽑아 읽을 수 있다는 것이 9일 내내 가장 크게 값을 냈다.
다만 **읽은 것을 그대로 되쓰면 안 된다.**

## 3.5 숫자가 말하는 것

- **문서가 63,854줄이고 그중 Terminal-Log가 35,101줄이다.**
  기록의 절반 이상이 "터미널이 뭐라고 말했는가"의 원문이다
- **시간의 상당 부분이 "이 툴로 이게 되나"에 들어갔다.** 블루프린트 자체는 어렵지 않았다.
  이건 개선 여지가 아니라 이 도구를 쓰는 비용이다
- **작은 수 세기를 여러 번 틀렸다** — `DrawRect` 12개(실제 4개), 변수 13개(실제 14개).
  개수는 세지 말고 `find_nodes`/`list_variables`의 결과 길이를 그대로 옮겨야 한다
- **커밋 116개 중 `docs:`가 절반 가까이다.** 기록에 들인 비용이 구현과 비슷하다
