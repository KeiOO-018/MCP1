## 8. Places where a tool's response disagreed with the read-back

1. **Write calls return `null` on success, not `true`.**
   `add_variable`, `set_variable_instance_editable` and `compile_blueprint` all returned
   `null`. Read-back confirmed all three variables exist with the requested types and that
   the Blueprint compiled. So `null` here means success, and the return value carries no
   information either way. By contrast `ObjectTools.set_properties` and
   `AssetTools.save_assets` both returned `true`. The return values of these tools are not a
   reliable success signal and were not used as one anywhere in this report.

2. **Instance Editable cannot be read back.**
   There is no `get_variable_instance_editable` in `BlueprintTools`. The flag was set by a
   write call that returned `null` (see item 1), so its state is asserted, not verified.
   This is the only unverified claim in this report.

3. **Float literals widen on read-back.**
   The colors were written as 0.1 / 0.8 / 0.9 / 0.2 and read back as 0.10000000149011612 /
   0.80000001192092896 / 0.89999997615814209 / 0.20000000298023224. This is FLinearColor's
   float32 channel storage printed as a double, not a value change.

4. **`type_name: "float"` produces a double-precision pin.**
   `HPBarHeight` was requested as `float`; the created Get node reports
   `Float (double-precision)`. This is UE5's normal Blueprint float, not a mismatch.

5. **Not a tool disagreement, but recorded because it changed between commands:**
   `git status` at the start of this session showed three modified Blueprints; it now shows
   only `BP_ThirdPersonHUD.uasset`. Two commits not made by this session appeared in the log
   in the meantime:

```
b62b669 docs(spec): inventory phase 2 spec
dc0b7ef feat(inventory): held item display, slot color fill, E use logic
```

   The character and player controller changes from earlier commands were committed outside
   this session. Nothing in this command touched those files.
