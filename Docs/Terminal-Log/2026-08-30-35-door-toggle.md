## 10. What is not verified

- **Nothing was run in PIE, and nothing calls `ToggleDoor`.** The event exists and compiles but
  has never fired — the lock check and interface implementation that would invoke it are
  command 36.
- **That the door visually swings correctly.** The maths reads correctly — `bOpen` flips, the
  new value picks `OpenAngle` or 0, that becomes a Yaw-only rotator, and the hinge moves to it
  over `1 / SwingSpeed` seconds — but no door has been placed in a level or watched. In
  particular unconfirmed: that yaw is the right axis for this hinge's orientation, and that
  `OpenAngle` 90 swings the door the way round the designer wants rather than into the frame.
- **That `1 / SwingSpeed` is a sensible duration.** With the default `SwingSpeed` = 1.0 that is
  1.0 second. A `SwingSpeed` of 0 would divide by zero; no guard was added because none was
  asked for, and UE returns a large finite value rather than crashing — but that was not tested.
- **That `MoveComponentTo` behaves correctly when re-triggered mid-move.** Pressing the toggle
  again before the first move finishes was not considered; the `Stop` and `Return` exec inputs
  were left unconnected as instructed.
