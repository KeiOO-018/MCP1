## 새 세션이 읽는 순서

1. **[AI-Log/](AI-Log/)의 가장 최근 파일**에서 `다음으로 넘김`을 읽는다.
   직전 세션이 아니라 **가장 최근 것**이다 — 기록은 띄엄띄엄 남는다
2. 이어서 할 일인지 접어둘 일인지 사용자에게 확인한다
3. 처리한 항목은 그 기록에서 지운다

`CLAUDE.md`의 `인계` 절이 이 순서를 정한다.

## 셋의 차이 — 헷갈리기 쉬운 자리

`Spec` · `AI-Log` · `Terminal-Log`가 같은 작업을 세 각도에서 남긴다.

| | 언제 쓰는가 | 무엇을 담는가 | 누가 쓰는가 |
|---|---|---|---|
| `Spec` | 구현 **전** | 만들 것과 안 만들 것, **합격 기준** | 나 (사용자 승인 후) |
| `Terminal-Log` | 명령 **중** | 터미널이 화면에 찍은 보고 원문 | 터미널이 직접 |
| `AI-Log` | 작업 **후** | 무엇이 됐고 무엇이 어긋났나 | 나 |

**합격 기준은 `Spec`에만 있다.** `AI-Log/_template.md`에 사양 칸도 합격 기준 칸도
없고 `확인한 것`은 결과만 적는다. 그래서 사양을 파일로 안 남기면
**"무엇을 통과로 쳤는가"가 세션과 함께 사라진다.**

## 두 번 겪은 실패 — 규칙이 이 파일에만 있으면 사라진다

`Terminal-Log`와 `Spec`이 **똑같은 이유로 끊겼다.**

| | 시작 | 끊긴 구간 | 원인 |
|---|---|---|---|
| `Terminal-Log` | 2026-08-29 | 2026-08-31 ~ 2026-09-03 | `CLAUDE.md`에 없었다 |
| `Spec` | 2026-08-28 | 2026-09-01 이후 | `CLAUDE.md`에 없었다 |

둘 다 관행으로만 존재했고, 새 세션은 `CLAUDE.md`를 읽지 폴더를 뒤지지 않는다.
**2026-09-03에 둘 다 `CLAUDE.md`에 넣었다.**

`Terminal-Log`는 끊긴 구간을 Claude Code 세션 기록에서 되찾아
[Terminal-Log/recovered/](Terminal-Log/recovered/)에 넣었다. `Spec`은 되찾지 않았다 —
사양은 대화의 산물이라 전부 남아 있지만, 그걸 옮기는 것은 **결정 사항이다.**
지금은 2026-09-03 것만 소급 작성돼 있다.

## 언어

문서는 한글로 쓴다. 다만 **터미널에 보내는 명령과 터미널의 보고는 영어가 원본이고,
그 원문을 번역하지 않는다.** 식별자(클래스명 · 함수명 · 변수명 · 플래그 · 에러 문구)도
영어 그대로 둔다 — 옮기면 검색도 엔진 문서 대조도 안 된다.
