## 이 사양이 딛고 선 것

### 도면과 사용자 확인 사항에서 이미 정해져 있던 것

[08-레벨-평면도.md](../ProjectICI5.8/08-레벨-평면도.md)의 `사용자가 확인해준 것` 절이
근거다. 아래는 **심문에서 묻지 않았다.** 이미 정해진 것이기 때문이다.

- 2층은 **로비에만** 있다. 방 1·2·3은 1층뿐이다
- 모양은 **`∩`** — 북·서·동 팔, **남쪽은 트여 있다**
- 팔 폭 **2칸 = `400`** (직전 세션에 확정)
- 계단은 **로비 북쪽 끝에 두 개**, 그 사이가 떠 있다
- 최종 문은 **2층 북쪽 팔 정중앙** = `Y 0`, 1층 `Door_R2`와 같은 `Y`
- 1층 로비 기둥이 그 복도를 받친다 (`2열 × 3행`). **북쪽 팔은 벽에 붙어 기둥이 없다**

좌표로 옮기면 (`+X = 북`, `+Y = 동`, 로비 실내 `X -1100..+1100` / `Y -1400..+1400`):

| 팔 | X | Y |
|---|---|---|
| 북 | `700 .. 1100` | `-1400 .. +1400` |
| 서 | `-1100 .. +700` | `-1400 .. -1000` |
| 동 | `-1100 .. +700` | `+1000 .. +1400` |

### 사용자가 고른 것

심문 일곱 항목 모두 항목별 안에서 골랐다.

- **A. 층고 = `a`** — 2층 바닥 `Z 600`. 기존 벽 `25`개는 **안 건드리고** 그 위에
  `Z 400..1200` 벽을 한 겹 더 얹는다. 도면의 층당 `600`을 지키면서 1층 문간·인방·문짝을
  손대지 않는다. 1층 천장고 `550`이라 점프해도(도달 `~250`, 머리 `~430`) 안 부딪힌다
- **B. 계단 = `a`** — 램프. `SM_Ramp` 하나를 늘려 경사로. 액터 둘로 끝나고 NavMesh가
  확실히 탄다 (대안: 큐브를 단마다 쌓아 계단 하나에 `30`개 / 램프 위에 큐브 몇 개)
- **C. 난간 = `a`** — 세운다. 높이 `100` 큐브 띠
- **D. 기둥 = `a`** — 세운다, 지름 `100` (대안: 지름 `200` / 안 세움)
- **E. 최종 문 뒤 = `a`** — **짧은 복도 + 막다른 방.** 거기 밟으면 `GAME CLEAR`.
  실제로 갈 데가 생긴다 (대안: 문간만 뚫고 트리거 / 문을 안 열고 문구만)
- **F. 적이 2층에 = `a`** — **안 온다.** NavMesh를 계단에 안 깔아도 된다
- **G. 이번 범위 = `b`** — **건축 + 최종 문 로직.** `ClearedRooms == 3` True 가지에
  문 여는 것까지 잇는다 (`c`의 `Build Paths`는 포함하지 않는다)

### 조사로 확인한 것 — 명령을 쓰기 전에 읽은 값

- **`SM_Ramp`** 바운드 `(0,0,0)~(100,100,100)`, **피벗이 최소 모서리** — `SM_Cube`와 같다
- **`SM_Cylinder`** 바운드 `(-50,-50,0)~(50,50,100)`, **피벗이 XY 중앙·바닥 `Z 0`**
- 레벨의 벽 액터 `25`개가 직전 세션 기록과 일치. 하단 `Z 0..200`, 상단 `Z 200..400`,
  둘 다 두께 `200`
- 로비 벽 발자국 — 서 `Y -1600..-1400`, 동 `Y 1400..1600`, 북 `X 1100..1300`,
  남 `X -1300..-1100`. `Door_R2` 문간은 `X 1100..1300 / Y -100..100 / Z 0..200`

## 범위

**만드는 것** — `Lvl_Stage`의 로비 위 2층 `∩` 발코니, 램프 두 개, 기둥 여섯, 난간,
2층 높이 외벽, 2층 북쪽 팔 정중앙의 `Door_Final`, 그 뒤 짧은 복도와 막다른 방,
클리어 트리거, 그리고 `ClearedRooms == 3`에서 `Door_Final`을 여는 연결.

**만들지 않는 것** — NavMesh 굽기(`G = b`라 `Build Paths` 안 함), 2층 적,
방 1·2·3의 2층, 램프 옆면 난간, 천장, 남쪽 장식 문.

**기존 액터는 하나도 안 건드린다.** 벽 `25`개·바닥 셋·문 셋·적 여섯은 그대로 두고
**위에 얹기만** 한다.

## 상태

새 상태는 하나뿐이다 — `Door_Final`의 열림/닫힘. 나머지는 전부 정적 지오메트리다.
클리어 트리거는 상태를 갖지 않고 **밟을 때마다 문구를 띄운다.**

## 권한

싱글이다. 리플리케이트하는 것 없음. **기존 네트워크 계약을 안 바꾼다.**

## 수명

전부 레벨에 배치되고 정리 주체가 없다. 스폰·파괴 없음.

## 튜닝 값의 주인

지오메트리는 레벨 액터의 트랜스폼(하드코딩). `BP_EndTrigger`의 박스 크기는
컴포넌트 기본값.

## 좌표

`+X = 북`, `+Y = 동`. `SM_Cube` 피벗 = 최소 모서리, 기본 `100³`.

| 것 | X | Y | Z |
|---|---|---|---|
| 2층 바닥 · 북 | `700 .. 1100` | `-1400 .. 1400` | `550 .. 600` |
| 2층 바닥 · 서 | `-1100 .. 700` | `-1400 .. -1000` | `550 .. 600` |
| 2층 바닥 · 동 | `-1100 .. 700` | `1000 .. 1400` | `550 .. 600` |
| 램프 서 | `-300 .. 700` | `-900 .. -300` | `0 .. 600` |
| 램프 동 | `-300 .. 700` | `300 .. 900` | `0 .. 600` |
| 2층 벽 | 로비 `4`면 | | `400 .. 1200` |
| `Door_Final` 문간 | `1100 .. 1300` | `-100 .. 100` | `600 .. 800` |
| 복도 | `1300 .. 1700` | `-100 .. 100` | 바닥 `600` |
| 막다른 방 | `1900 .. 2700` | `-600 .. 600` | 바닥 `600` |

기둥은 `SM_Cylinder`, 지름 `100`, `Z 0 .. 550`, 자리는
`(-800 / -200 / 400)` × `(Y -1000 / Y 1000)` 여섯이다.

## 내가 정한 값 — 사용자가 말한 것이 아니다

- 램프 수평 길이 `1000`, 폭 `600`, 사이 틈 `Y -300..300` — **도면에 계단 치수가 없다**
- 기둥 X 좌표 `-800 / -200 / 400`(간격 `600`) — 도면은 "3개"만 말한다
- 복도 길이 `400`, 막다른 방 `800 × 1200` — **도면에 없는 구역이다**
- 2층 벽 꼭대기 `1200`(층당 `600` × 2층) — 도면의 모듈 치수에서 따왔다
- 난간 두께 `100`, 팔 안쪽 가장자리 안쪽에 붙임

## 합격 기준

> 1. **PIE에서** 로비 북쪽 램프를 걸어 올라가면 **2층 바닥(`Z 600`)에 선다.**
> 2. **PIE에서** 2층 팔의 안쪽 가장자리로 걸어가면 **난간에 막혀 로비로 안 떨어진다.**
> 3. **PIE에서** 방 셋을 다 클리어하면 **`Door_Final`이 저절로 열린다.**
> 4. **PIE에서** 열린 `Door_Final`을 지나 막다른 방에 들어서면 **`GAME CLEAR`가 뜬다.**

이 넷으로만 검증한다. 여기 없는 것은 "확인 안 됨"이다.

**결과** — 사용자가 PIE에서 다섯을 다 돌리고(위 넷 + 클리어 전 `DOOR IS LOCKED` 확인)
"이상 없음"으로 답했다. **AI가 화면을 본 적은 없다.**

## 미리 아는 구멍 — 사양 확정 시점에 적어둔 것

- **`SM_Ramp`가 어느 축으로 올라가는지 모른다.** 바운드가 `100³` 정육면체라 방향이
  안 보인다. **명령 2에서 한 개만 놓고 `trace_world`로 실측한 뒤** 나머지를 정한다
- **`BP_Door`의 잠금 처리를 아직 안 읽었다.** `Door_Final`을 `bLocked`로 잠글지
  `bSealed`로 잠글지는 **`Event Interact` 그래프를 읽고 정한다**
  (`bSealed`는 Instance Editable이 OFF라 레벨에서 못 켠다)
- **램프 옆면 난간은 이번에 안 만든다.** 램프에서 옆으로 떨어질 수 있다

## 사양을 쓴 뒤 조사로 닫힌 구멍

- **`SM_Ramp`는 `rotation (0,0,0)`일 때 `-Y`로 오른다.** `trace_world` 다섯 발로
  실측했다. 사양의 예상("`+X`로 오른다")이 **틀렸다.** `yaw 90` + 스케일을
  `(10,6,6)` → `(6,10,6)` + 위치 `X -300` → `700`으로 세 값을 같이 고쳤다
- **`bLocked = true` + `RequiredKey` 비움으로 간다.** `TryConsumeSelected`를 읽으니
  `bMatched = (InventorySlots[idx] == RowName) AND (RowName != "")`이라 **빈 열쇠는
  절대 성공하지 못한다.** `BP_Door`도 `BP_ThirdPersonCharacter`도 안 고쳤다
- **`BP_Door`의 CDO 기본값이 `bLocked true` · `RequiredKey = Key_Stage1`이다.**
  안 비웠으면 최종 문이 1스테이지 열쇠로 열리는 문이 됐다

## 남는 위험

- **최종 구역이 방2 위 허공에 떠 있다.** 방2엔 천장이 없으므로 안에서 위를 보면 보인다
- **램프 옆면에 난간이 없다.** 경사면이라 회전한 큐브가 필요해서 뺐다
- **난간이 `100`이라 점프(도달 `~250`)로 넘어간다.** `C = a`가 그 값이었다
- **`Wall_2F_S`가 로비 구간(`Y -1400..1400`)만 높다.** 방1·방3 쪽 남쪽 벽은 `Z 400`이다
- **`NavBounds_Main`이 `Z -200..600`이라 2층 바닥(`Z 600`)이 경계에 정확히 걸쳐 있다.**
  `Build Paths`를 돌리면 그때 2층에 NavMesh가 깔리는지 드러난다
- **`GAME CLEAR`가 재입장 때마다 다시 뜬다.** 상태 변수를 안 만들기로 했다
- **`ClearedRooms == 3`의 `3`이 그래프 리터럴이다.** 방이 넷이 되면 여기와
  `bIsFinalRoom` 두 곳을 고쳐야 한다. 지금은 셋뿐이라 정당화되지 않는 일반화다
- **`Door_Final`을 여는 노드에 `bOpen` 검사가 없다.** `BP_StageRoom`은 두는데 여긴
  안 뒀다. `NotifyRoomCleared`가 한 번만 걸리므로 지금은 필요 없다

## 명령 계획

한 번에 하나씩, 앞 결과를 보고 다음으로 간다.

1. 2층 바닥 셋
2. **램프 한 개만 시험 배치** — 경사 방향을 실측하려고 하나만 놓는다
3. `Ramp_W` 고치고 `Ramp_E` 추가
4. 2층 벽 일곱 (`Door_Final` 문간을 내려고 북쪽 벽을 네 조각으로)
5. 난간 다섯 · 기둥 여섯
6. 최종 구역 아홉 (복도 + 막다른 방)
7. `Door_Final` — **`BP_Door`를 읽고 잠금 방식을 정한 뒤**
8. `BP_EndTrigger` 신설
9. `EndTrigger` 배치
10. 게임모드 `NotifyRoomCleared`에 문 여는 것 잇기
11. (계획에 없던 것) 램프가 삼킨 포션 두 개 이동
12. 저장

**실제로 명령 11이 늘었다.** 램프가 사용자가 놓은 포션 둘(`(170,-430,20)` ·
`(-160,-440,20)`)을 통째로 삼킨 것을 검증 중에 발견했고, 사용자가 "스폰 뒤쪽으로"를
지정해 `(-600,-430,20)` · `(-900,-440,20)`으로 옮겼다.
