# 사양 · 플레이어 사망과 리스폰

2026-09-01 확정. **합격 기준 넷이 전부 통과했다.**

적 AI가 [복귀](2026-08-31-적-AI-복귀.md)까지 완성된 뒤, 인계 목록의 다음 항목이
`적의 HP · 피격 · 사망`이었는데 **조사해보니 그건 지금 만들 수 없다.**
플레이어에게 공격 수단이 없어서 "적을 때리면 ___가 된다"는 합격 기준을 쓸 방법이 없다.
`Input/Actions/`에 `IA_Attack`이 없고 `BP_ThirdPersonCharacter`의 변수 열하나에도
공격 관련이 하나도 없다.

**반면 플레이어 사망은 재료가 이미 다 있었다.** 그래서 순서를 바꿔 이것을 먼저 만들었다.

---

## 이 사양이 딛고 선 것

### 이미 있던 것 — 새로 만들 게 거의 없었다

- **`CurrentHP` · `MaxHP` 변수.** 기본값 `75` / `100`
- **`Event AnyDamage`가 구현돼 있다** (명령 60). 노드 다섯이 전부였다

  ```
  Event AnyDamage → Set CurrentHP = Clamp(CurrentHP − Damage, 0, MaxHP)
  ```

  **`Set CurrentHP`의 `then` 핀이 아무 데도 안 이어져 있었다.** 거기가 붙일 자리였다
- **HUD가 HP 바를 이미 그린다.** `BP_ThirdPersonHUD`의 `EventReceiveDrawHUD`가
  `ColorHPBack` 배경 위에 `ColorHPFill`을 `CurrentHP / MaxHP` 비율로 그린다
- **HUD의 `CachedCharacter` 재획득 분기가 이미 있다.** `IsValid` 실패 시
  `GetControlledPawn` → `Cast` → `SetCachedCharacter`. **폰이 파괴돼도 HUD가 알아서 잡는다**
- **적의 `NO_PLAYER` 분기.** `PlayerRef`가 무효면 `GetPlayerCharacter(0)`로 다시 잡는다.
  만들어만 두고 한 번도 실행된 적이 없던 경로다
- **적이 실제로 데미지를 넣는다.** `ApplyDamage(PlayerRef, AttackDamage 10, ...)`
- **`GameMode` 설정이 정상이다.** `DefaultPawnClass` = `BP_ThirdPersonCharacter`,
  `HUDClass` = `BP_ThirdPersonHUD`, `PlayerControllerClass` = `BP_ThirdPersonPlayerController`.
  `PlayerStart`는 레벨에 하나뿐이다
- **사망 애니메이션 6개**(`MM_Death_Back_01` · `Front_01/02/03` · `Left_01` · `Right_01`).
  **애님 시퀀스라 몽타주는 새로 만들어야 한다.** 이번엔 안 썼다

### 사용자가 고른 것

심문 두 항목 모두 항목별 안에서 골랐다.

- **`RestartPlayer`로 폰을 새로 스폰한다** (같은 폰 텔레포트 / 레벨 리로드 중 택1)
- **연출 없이 N초 뒤 리스폰** (사망 몽타주 / 래그돌 중 택1)

### 조사로 확인한 노드

전부 엔진 소스에서 시그니처를 읽었다.

| 함수 | 선언 위치 | |
|---|---|---|
| `AGameModeBase::RestartPlayer(AController*)` | `GameModeBase.h:434` | `BlueprintCallable` |
| `APawn::DetachFromControllerPendingDestroy()` | `Pawn.h:468` | `BlueprintCallable` |
| `AActor::DisableInput(APlayerController*)` | `Actor.h:1435` | `BlueprintCallable` |
| `UGameplayStatics::GetGameMode()` | `GameplayStatics.h:364` | `BlueprintPure`, **`AGameModeBase*` 반환** |

**`GetGameMode`가 `AGameModeBase*`를 돌려주고 `RestartPlayer`가 거기 선언돼 있으므로
캐스트 노드가 필요 없다.**

---

## 범위

**만드는 것** — `BP_ThirdPersonCharacter` 하나만 고친다.

- `Event AnyDamage`에 죽음 판정과 리스폰 사슬을 붙인다
- 새 변수 하나 `RespawnDelay`

**만들지 않는 것**

- **사망 애니메이션 · 몽타주 · 래그돌.** 사용자가 `연출 없이`를 골랐다
- **시체 남기기.** 폰을 파괴한다
- **사망 시 아이템 드롭.** `BP_ItemPickup`과 `IA_DropItem`이 있어 만들 수는 있지만 안 했다
- **게임오버 화면 · 사망 카운트 · 체크포인트**
- **HUD 변경.** HP 바도 재캐시 분기도 이미 있다
- **적 쪽 변경.** `NO_PLAYER` 분기가 이미 처리한다
- **새 BP · 컴포넌트 · 인터페이스**

---

## 상태

**새 상태 변수를 안 만든다. `CurrentHP`가 곧 상태다.**

```
CurrentHP >  0   살아 있음
CurrentHP <= 0   죽음
```

데미지 처리 자체를 `CurrentHP > 0`으로 가드한다. 그래서 **죽은 뒤 들어오는 데미지는
아무 일도 안 하고 죽음 사슬을 다시 안 탄다.** `bIsDead` 불리언이 필요 없다 —
결정 사다리 1번(안 만들어도 되는가).

리스폰하는 동안 적이 계속 때리는데(로그에 `ATTACK`이 8대째 이후로도 찍힌다)
가드 덕분에 `RestartPlayer`가 여러 번 예약되지 않는다.

---

## 권한 / 수명 / 튜닝 값의 주인

- **권한** — 싱글. 리플리케이션 없음
- **수명** — 죽은 폰이 자기를 `DestroyActor`로 정리한다. 새 폰은 GameMode의
  `RestartPlayer`가 `PlayerStart`에 스폰한다
- **튜닝 값의 주인** — `RespawnDelay`는 `BP_ThirdPersonCharacter`의 인스턴스 편집 변수,
  기본값 `2.0`. **`CurrentHP 75` · `MaxHP 100`은 안 건드렸다**

---

## 완성 후의 사슬

```
Event AnyDamage
  → Branch (CurrentHP > 0)
      False → 끝
      True  → Set CurrentHP = Clamp(CurrentHP − Damage, 0, MaxHP)      [기존 노드]
              → Branch (CurrentHP <= 0)
                  False → 끝
                  True  → DisableInput (self, Get Player Controller 0)
                          → Delay (RespawnDelay)
                          → DetachFromControllerPendingDestroy (self)
                          → RestartPlayer (target = Get Game Mode,
                                           NewPlayer = Get Player Controller 0)
                          → DestroyActor (self)
```

### 순서에 이유가 있다

**`DetachFromControllerPendingDestroy`가 반드시 `RestartPlayer` 앞이다.**
소스에서 확인했다 — `AGameModeBase::RestartPlayerAtPlayerStart`가 이렇다.

```cpp
	if (NewPlayer->GetPawn() != nullptr)
	{
		// If we have an existing pawn, just use it's rotation
		SpawnRotation = NewPlayer->GetPawn()->GetActorRotation();
	}
	else if (GetDefaultPawnClassForController(NewPlayer) != nullptr)
	{
		// Try to create a pawn to use of the default class for this player
		APawn* NewPawn = SpawnDefaultPawnFor(NewPlayer, StartSpot);
```

**컨트롤러가 폰을 아직 들고 있으면 새 폰을 안 만든다.** 회전만 가져가고 끝난다.
그냥 `RestartPlayer`를 부르면 아무 일도 안 일어난다.

**컨트롤러를 `Get Player Controller (0)`으로 가져온다.** `GetController(self)`가 아니다 —
떼어낸 뒤에는 널이 된다. 순서 함정을 아예 없애는 쪽을 골랐다.

**`RestartPlayer` 본문에 `PlayerCanRestart` 게이트가 없다.** 막힐 데가 없다.

## 합격 기준

> 1. PIE에서 적에게 계속 맞아 HP 바가 0이 되면,
>    **2초 뒤 플레이어가 `PlayerStart`에서 다시 시작한다.**
> 2. 리스폰 직후 HP 바가 **처음 PIE를 켰을 때와 같은 길이다** (`CurrentHP 75` / `MaxHP 100`).
> 3. 리스폰 직후 인벤토리 세 칸이 **전부 비어 있다.** 죽기 전에 들고 있던 것이 사라진다.
> 4. 리스폰한 뒤 2번 방으로 다시 들어가면 **적이 다시 쫓아온다.**

**검증은 이 넷으로만 한다. 여기 없는 것은 "확인 안 됨"이다.**

**2026-09-01 현재 넷 다 통과했다.**

| 기준 | 상태 | 근거 |
|---|---|---|
| 1 | 통과 | 로그. `AttackDamage 10`에 `CurrentHP 75`니 8대째가 치명타다. 1주기 8대째 `15:11:03.191` + `RespawnDelay 2.0` = `15:11:05.19`, 파괴 창은 9번째 공격 `15:11:04.701`과 `NO_PLAYER` `15:11:06.206` 사이 — 그 안이다. 2주기도 같다(8대째 `15:11:31.617`, 창 `33.429`~`34.933`) |
| 2 | 통과 | PIE 실측. 리스폰한 폰 `BP_ThirdPersonCharacter_C_2`에서 `CurrentHP 75` · `MaxHP 100` |
| 3 | 통과 | 사용자 육안. 물약을 들고 죽었고 부활 시 세 칸 다 비었다 |
| 4 | 통과 | 로그. `NO_PLAYER`(`15:11:06.206`) → 13초 뒤 `ATTACK`(`15:11:19.574`), 2차도 `NO_PLAYER`(`15:11:34.933`) → `CHASE`(`15:11:47.739`) |

**`NO_PLAYER`가 이 프로젝트에서 처음 로그에 찍혔다.** 폰이 실제로 파괴됐다는 직접 증거이고,
동시에 적의 재획득 경로가 처음 실행된 순간이다.

**덤으로 확인된 것 둘** — 기준에 없어서 판정에는 안 넣는다.

- **`DisableInput`이 먹는다.** 죽은 시점부터 부활까지 안 움직인다 (육안)
- **무조건 3인칭으로 부활한다.** 아래 `남는 위험` 참조 (육안)

## 남는 위험

- **`bIsFirstPerson`이 클래스 기본값 `false`로 돌아간다.** 1인칭으로 플레이하다 죽으면
  **3인칭으로 부활한다.** `RestartPlayer`가 새 폰을 만드는 이상 피할 수 없다.
  고치려면 죽기 전 값을 폰 밖(PlayerController나 GameInstance)에 넘겨야 하는데
  지금 구조에 그 자리가 없다. **사용자가 `내비두자`로 정했다**
- **리스폰 지점에 적이 있을 수 있다.** 적이 1번 방까지 쫓아온 상태로 죽으면
  `PlayerStart` 근처에서 바로 다시 맞는다
- **2초 동안 화면에 아무 표시가 없다.** 입력만 막힌 채 서 있는다. `연출 없이`로 정한 결과다
- **`DisableInput`이 Enhanced Input 매핑까지 막는지는 소스로 확인 안 했다.**
  PIE에서 안 움직이는 것만 봤다
- **HUD의 `CachedCharacter` 재획득은 그래프로만 확인했다.** PIE에서 HP 바가 계속
  그려지는 것은 봤지만 재캐시가 실제로 일어났는지 따로 확인하지는 않았다
- **`NO_PLAYER` 분기에 `StopMovement`가 없다.** 지금은 문제가 안 된다 —
  `PlayerRef`가 무효가 된 직후 바로 다시 잡히기 때문이다. **적 HP·사망을 만들 때 다시 본다**

## 명령 계획

| 명령 | 내용 | 상태 |
|---|---|---|
| 72 | `RespawnDelay` 추가 + `Event AnyDamage` 사슬 확장 | 완료 |
| 73 | PIE로 **합격 기준 1~4** | 완료 · 1·2·4는 로그/실측, 3은 표본 부실 |
| 74 | PIE로 **기준 3만 다시** (물약을 들고 죽기) | 완료 · 통과 |

**명령 73에서 기준 3이 한 번 헛돌았다.** 그때 주운 것이 열쇠 하나뿐이었는데
열쇠는 문을 열 때 소비되므로([문과 상호작용](2026-08-30-문과-상호작용.md)의 합격 기준 2)
죽기 전에도 인벤토리가 비어 있었다. **빈 슬롯이 근거가 안 됐다.**
레벨의 `BP_ItemPickup`이 6개에서 5개로 하나만 줄어든 것으로 알아냈다.
명령 73·74는 Terminal 명령이 아니라 한글로 낸 PIE 플레이 절차다.
