# 사양 · 적 AI 복귀

2026-08-31 확정. [적 AI 1단계](2026-08-30-적-AI-1단계.md)의 합격 기준 다섯이
전부 통과한 뒤 사용자가 이어서 요청한 증분이다.

**구현은 끝났고 PIE 검증은 안 됐다.** 아래 `합격 기준` 다섯이 전부 미확인이다.

## 이 사양이 딛고 선 것

### 사용자가 정한 것

심문 다섯 항목 중 **둘은 사용자가 직접 답했고 셋은 항목별 안에서 골랐다.**

- **시간은 현실시간 7초.** `Think` 횟수를 세지 않고 실제 초를 잰다
- **집은 각자의 스폰 지점.** "적 AI가 각각 스폰 구역을 가지고 스폰 구역으로 가는건 어때"
- **도착하면 초기 방향으로 돌아선다.** "그래야 처음 배치할 때 원하는 위치를 바라보게 배치하니까"
- **복귀 중 감지는 짧은 홉으로 실제 작동시킨다** (한 번에 가고 도착 후에만 재평가 중 택1)
- **시야각은 나중에.** 이번엔 작은 구형만 (지금 같이 넣는다 중 택1)
- **30초 갇힘 사망은 이번에 안 넣는다** (지금 넣는다 중 택1)

### 사용자가 그린 전체 그림 — 이번에 반만 만든다

원문은 이렇다.

> 원래 적이 감지 할 수 있는 구형 범위가 있고 나중에 시야각도 넣을거야 시야각에서
> 거리가 있을거 아니야 그게 구형 범위의 반지름이 되는거임 돌아 갈 때는 (복귀할 때)
> 적 AI의 시야각 범위랑, 작은 구형 범위를 하나 더 지정해서 쓸건데 (…) 기존에 큰
> 구형은 복귀 때는 꺼지고, 그러면 보통 플레이어가 뒤에서 습격하려고 가까이 갈거
> 아니야? 그러면 그 작은 구형에 범위에 들어가면 플레이어를 인지하는거지

**이번 사양은 "작은 구형"만 만든다.** 시야각이 아직 없기 때문이다
([적 AI 1단계](2026-08-30-적-AI-1단계.md)의 `만들지 않는 것`이 `시야각 · 라인 오브 사이트`를
명시적으로 미뤄뒀다).

그래서 **복귀 중 정면 중거리에 서 있는 플레이어는 못 본다.** 뒤·옆 급습은 잡히고,
정면은 집에 도착해 큰 구형이 켜져야 잡힌다. 시야각이 생기면 복귀 중 감지에
`OR`로 붙이면 된다 — 구조는 그대로 둔다.

### 조사로 확인한 노드

전부 `get_node_type_pins`로 핀 이름과 타입을 읽었다.

| type_id | 핀 |
|---|---|
| `Utilities|Time|GetGameTimeinSeconds` | → `ReturnValue` double. 순수 |
| `Math|Vector|VectorLength` | `A:Vector` → double. 순수 |
| `Math|Vector|Normalize` | `A:Vector` · `Tolerance=0.0001` → Vector. 순수 |
| `Math|Float|Min(Float)` | `A` · `B` double → double. 순수 |
| `Transformation|GetActorLocation` | `self:Actor` → Vector. 순수 |
| `Transformation|GetActorRotation` | `self:Actor` → Rotator. 순수 |
| `Transformation|SetActorRotation` | `self` · `NewRotation` · `bTeleportPhysics=false` |

`GetDirectionUnitVector`는 없다. **빼기 + `Normalize` 두 노드로 대신한다.**

## 범위

**만드는 것** — `BP_Enemy` 하나만 고친다.

- **복귀 판정** — 마지막 감지 후 `ReturnDelay`가 지나고 집에서 멀면 복귀 중
- **짧은 홉 이동** — 집까지 한 번에 안 가고 `ReturnStepDistance`씩 끊어 가며
  매 홉마다 다시 감지한다
- **감지 반경 전환** — 평소 `SightRange`, 복귀 중 `ReturnSightRange`
- **도착 시 초기 회전 복원**

**만들지 않는 것**

- **시야각.** 위 참조
- **30초 갇힘 사망.** 적 HP·피격·사망을 제대로 만들 때 같이 한다.
  사용자가 "진짜 진짜 예외상황을 위해서 두는 장치"라고 했고, 방 안에서만 도는
  기획이라 실제로 안 걸린다. **결정 사다리 1번 — 안 만들어도 된다**
- **StateTree · BehaviorTree.** 아래 `상태` 참조
- **순찰 · 배회.** 집에 도착하면 그 자리에 선다
- **새 블루프린트 · 새 컴포넌트.** 하나도 없다

**대상** — `Content/Enemy/BP_Enemy` 하나.

## 상태

**저장되는 런타임 값은 `LastSeenTime` 하나다.**

`HomeLocation`·`HomeRotation`은 `BeginPlay`에서 굳히는 상수라 상태가 아니다.
**"복귀 중인가"를 플래그로 저장하지 않고 매번 계산한다.**

```
returning = (now − LastSeenTime >= ReturnDelay) AND (homeDist > HomeArriveRadius)
```

집에 서 있으면 `homeDist ≈ 0`이라 **거짓** → 큰 구형으로 경계한다.
스폰 직후 플레이어를 한 번도 못 봐도 마찬가지라
[적 AI 1단계](2026-08-30-적-AI-1단계.md)의 합격 기준 1·2가 안 깨진다.

### 왜 상태 기계를 안 뽑았나

1단계 사양이 **"행동이 넷째·다섯째로 늘면 그때 뽑는다"**고 적어뒀고,
복귀가 정확히 넷째 행동이다(경계 · 추격 · 공격 · 복귀).

**그런데 뽑지 않았다.** 모드가 타임스탬프 하나에서 파생되기 때문이다.
분기가 하나 더 붙을 뿐이고, 1단계 사양의 무상태 규칙
(`거리는 매번 다시 잴 수 있다. 재면 되는 것을 저장하지 않는다`)이 그대로 유지된다.

**시야각이 붙거나 순찰이 생기면 이 판단을 다시 본다.**

## 새 변수 일곱

| 변수 | 타입 | 기본값 | 인스턴스 편집 | 무엇 |
|---|---|---|---|---|
| `ReturnDelay` | float | `7.0` | ✓ | 마지막 감지 후 이만큼 지나면 복귀 |
| `ReturnSightRange` | float | `300.0` | ✓ | 복귀 중에만 쓰는 작은 구형 반지름 |
| `ReturnStepDistance` | float | `300.0` | ✓ | 복귀 한 홉 거리 |
| `HomeArriveRadius` | float | `100.0` | ✓ | 이 안이면 집에 도착 |
| `HomeLocation` | Vector | — | ✗ | `BeginPlay`의 `GetActorLocation` |
| `HomeRotation` | Rotator | — | ✗ | `BeginPlay`의 `GetActorRotation` |
| `LastSeenTime` | float | `0.0` | ✗ | 마지막 감지 시각 |

**사용자가 준 숫자는 `7초` 하나다.** 나머지 셋(`300` · `300` · `100`)은 AI가 정했다.
`300`은 캡슐 반지름 35의 여덟 배쯤이고 속도 300에서 1초 거리다.
**눈으로 보고 조절할 값이라 전부 인스턴스 편집으로 뺐다.**

## 완성 후의 호출 구조

```
BeginPlay
  → PlayerRef    = Get Player Character(0)
  → HomeLocation = GetActorLocation
  → HomeRotation = GetActorRotation
  → LastSeenTime = Get Game Time in Seconds
  → Think

Think
  IsValid(PlayerRef)?
    거짓 → PlayerRef 재획득 → Delay(ThinkInterval) → Think

    참:
      now       = Get Game Time in Seconds
      d         = GetDistanceTo(PlayerRef)
      selfLoc   = GetActorLocation
      toHome    = HomeLocation − selfLoc
      homeDist  = VectorLength(toHome)
      returning = (now − LastSeenTime >= ReturnDelay) AND (homeDist > HomeArriveRadius)
      radius    = returning ? ReturnSightRange : SightRange

      d <= radius ?
        참  → LastSeenTime = now
              d <= AttackRange ?
                참  → 몽타주 → ApplyDamage → Delay(AttackCooldown) → Think
                거짓 → AI MoveTo(TargetActor=PlayerRef, Accept=AttackRange−20)
                         OnSuccess / OnFail → Delay(ThinkInterval) → Think
        거짓 → returning ?
                참  → step = selfLoc + Normalize(toHome) × Min(ReturnStepDistance, homeDist)
                       AI MoveTo(Destination=step, Accept=HomeArriveRadius)
                         OnSuccess / OnFail → Delay(ThinkInterval) → Think
                거짓 → homeDist <= HomeArriveRadius ?
                         참  → SetActorRotation(HomeRotation) → Delay → Think
                         거짓 → Delay(ThinkInterval) → Think
```

**`Think`로 돌아가는 경로가 여덟이고 여덟 다 앞에 지연이 있다.**
1단계 사양의 핵심 규칙이 유지된다.

`Min(ReturnStepDistance, homeDist)`가 홉을 집까지 거리로 자른다 — **집을 지나치지 않는다.**

`LastSeenTime`을 `BeginPlay`에서 `now`로 초기화한다. 안 하면 `0`이라 시작하자마자
`elapsed`가 거대해진다. 집에 있으니 동작엔 지장 없지만 의미가 틀린다.

## 권한 / 수명 / 튜닝 값의 주인

- **싱글플레이.** 리플리케이션을 추가하지도 제거하지도 않는다
- **정리할 타이머가 없다.** `Set Timer`를 안 쓰고 `Delay`·`AI MoveTo`는 라텐트라
  액터가 파괴되면 엔진이 취소한다. `EndPlay`를 구현하지 않는다
- **튜닝 값 넷은 인스턴스 편집 변수.** 적마다 다르게 줄 수 있다
- **`HomeLocation`/`HomeRotation`의 주인은 레벨 배치 트랜스폼이다.**
  따로 지정하지 않는다 — **배치한 자리가 곧 집이고 배치한 방향이 곧 초기 방향이다**

## 합격 기준

> 1. PIE에서 적을 유인한 뒤 `SightRange` 밖으로 도망치면,
>    **7초 뒤 적이 스폰 지점으로 걸어간다.**
> 2. PIE에서 적이 복귀하는 동안 뒤에서 `ReturnSightRange` 안으로 접근하면,
>    **적이 다시 나를 쫓아온다.**
> 3. PIE에서 적이 복귀하는 동안 `ReturnSightRange` 밖에서 따라가면,
>    **적이 무시하고 집까지 간다.**
> 4. PIE에서 적이 집에 도착하면, **처음 배치했을 때의 방향으로 돌아서서 선다.**
> 5. PIE에서 집에 선 적에게 `SightRange` 안으로 접근하면, **다시 쫓아온다.**

**검증은 이 다섯으로만 한다. 여기 없는 것은 "확인 안 됨"이다.**

**2026-08-31 현재 다섯 다 미확인이다.**

## 남는 위험

- **`SetActorRotation`이 `bOrientRotationToMovement`와 싸울 수 있다.**
  무브먼트 컴포넌트가 속도 방향으로 회전을 몬다. 멈춰 있으면 안 싸울 것으로 보지만
  **확인 안 했다.** 합격 기준 4가 이것을 본다
- **`ReturnStepDistance 300`이면 1초에 한 번만 감지한다.** 속도 600인 플레이어는
  그 사이 600을 움직이므로 `ReturnSightRange 300`을 스쳐 지나갈 수 있다.
  기준 2에서 안 잡히면 **홉을 줄이는 것이 첫 수다**

## 이번에 부딪힌 함정 — 배치 순서

**첫 PIE에서 적이 145 거리에서도 반응하지 않았다.**

정적 분석으로는 못 찾았다. 그래프는 완벽했고 실행 사슬도 끊긴 데가 없었다.
**PIE 중에 `Enemy_Test`의 실제 변수를 읽어서 잡았다.**

```
ReturnSightRange   0     ← 300이어야 한다
ReturnDelay        0     ← 7
ReturnStepDistance 0     ← 300
HomeArriveRadius   0     ← 100
SightRange       1200    ← 옛 변수는 정상 상속
ThinkInterval     0.3    ← 옛 변수는 정상 상속
```

```
returning = (now − 0 >= 0) AND (0.25 > 0) = 참        ← 시작하자마자 계속 복귀 중
radius    = ReturnSightRange = 0
d ≈ 145  <=  0  거짓                                   ← 영원히 감지 실패
홉        = Min(0, 0.25) = 0                           ← 제자리로 이동 명령
```

**원인은 배치 순서다.** 인스턴스를 먼저 놓고 나중에 변수를 추가하면
그 인스턴스에 `0` 오버라이드가 박히고, 나중에 바뀐 클래스 기본값을 따라오지 않는다.
`MaxWalkSpeed 600 → 300` 때와 같은 종류다.

명령 66에서 인스턴스 값을 클래스 기본값과 **같게** 맞추자 오버라이드가 걷혔다 —
델타가 없어져서 외부 액터 파일이 커밋 시점과 바이트까지 동일해졌다.

**적을 새로 배치할 때는 변수를 다 만든 뒤에 놓는다.**
