# 사양 · 적 AI 복귀

2026-08-31 확정. [적 AI 1단계](2026-08-30-적-AI-1단계.md)의 합격 기준 다섯이
전부 통과한 뒤 사용자가 이어서 요청한 증분이다.

**2026-08-31 저녁 기준 합격 기준 다섯이 전부 통과했다.** 다만 통과까지 버그를 둘 고쳤다 —
`AI MoveTo`가 래턴트라 추격 중 `Think`가 멈추던 것과, `AI MoveTo`의 도달 판정이
`AcceptanceRadius`에 에이전트 반지름을 더해 `HomeArriveRadius`와 어긋나던 것이다.
아래 `추격 중 재평가 — 명령 68의 증분`과 `이번에 부딪힌 함정 둘`을 함께 읽는다.

## 이 사양이 딛고 선 것

### 사용자가 정한 것

심문 다섯 항목 중 **둘은 사용자가 직접 답했고 셋은 항목별 안에서 골랐다.**

- **시간은 현실시간 7초.** `Think` 횟수를 세지 않고 실제 초를 잰다
- **집은 각자의 스폰 지점.** "적 AI가 각각 스폰 구역을 가지고 스폰 구역으로 가는건 어때"
- **도착하면 초기 방향으로 돌아선다.** "그래야 처음 배치할 때 원하는 위치를 바라보게 배치하니까"
- **복귀 중 감지는 짧은 홉으로 실제 작동시킨다** (한 번에 가고 도착 후에만 재평가 중 택1)
- **시야각은 나중에.** 이번엔 작은 구형만 (지금 같이 넣는다 중 택1)
- **30초 갇힘 사망은 이번에 안 넣는다** (지금 넣는다 중 택1)

### 사용자가 그린 전체 그림 — 이번에 반만 만든다

원문은 이렇다.

> 원래 적이 감지 할 수 있는 구형 범위가 있고 나중에 시야각도 넣을거야 시야각에서
> 거리가 있을거 아니야 그게 구형 범위의 반지름이 되는거임 돌아 갈 때는 (복귀할 때)
> 적 AI의 시야각 범위랑, 작은 구형 범위를 하나 더 지정해서 쓸건데 (…) 기존에 큰
> 구형은 복귀 때는 꺼지고, 그러면 보통 플레이어가 뒤에서 습격하려고 가까이 갈거
> 아니야? 그러면 그 작은 구형에 범위에 들어가면 플레이어를 인지하는거지

**이번 사양은 "작은 구형"만 만든다.** 시야각이 아직 없기 때문이다
([적 AI 1단계](2026-08-30-적-AI-1단계.md)의 `만들지 않는 것`이 `시야각 · 라인 오브 사이트`를
명시적으로 미뤄뒀다).

그래서 **복귀 중 정면 중거리에 서 있는 플레이어는 못 본다.** 뒤·옆 급습은 잡히고,
정면은 집에 도착해 큰 구형이 켜져야 잡힌다. 시야각이 생기면 복귀 중 감지에
`OR`로 붙이면 된다 — 구조는 그대로 둔다.

### 조사로 확인한 노드

전부 `get_node_type_pins`로 핀 이름과 타입을 읽었다.

| type_id | 핀 |
|---|---|
| `Utilities|Time|GetGameTimeinSeconds` | → `ReturnValue` double. 순수 |
| `Math|Vector|VectorLength` | `A:Vector` → double. 순수 |
| `Math|Vector|Normalize` | `A:Vector` · `Tolerance=0.0001` → Vector. 순수 |

| `Transformation|SetActorRotation` | `self` · `NewRotation` · `bTeleportPhysics=false` |

`GetDirectionUnitVector`는 없다. **빼기 + `Normalize` 두 노드로 대신한다.**

## 범위

**만드는 것** — `BP_Enemy` 하나만 고친다.

- **복귀 판정** — 마지막 감지 후 `ReturnDelay`가 지나고 집에서 멀면 복귀 중
- **짧은 홉 이동** — 집까지 한 번에 안 가고 `ReturnStepDistance`씩 끊어 가며
  매 홉마다 다시 감지한다
- **감지 반경 전환** — 평소 `SightRange`, 복귀 중 `ReturnSightRange`
- **도착 시 초기 회전 복원**

**만들지 않는 것**

- **시야각.** 위 참조
- **30초 갇힘 사망.** 적 HP·피격·사망을 제대로 만들 때 같이 한다.
  사용자가 "진짜 진짜 예외상황을 위해서 두는 장치"라고 했고, 방 안에서만 도는
  기획이라 실제로 안 걸린다. **결정 사다리 1번 — 안 만들어도 된다**
- **StateTree · BehaviorTree.** 아래 `상태` 참조
- **순찰 · 배회.** 집에 도착하면 그 자리에 선다
- **새 블루프린트 · 새 컴포넌트.** 하나도 없다

**대상** — `Content/Enemy/BP_Enemy` 하나.

## 상태

**저장되는 런타임 값은 `LastSeenTime` 하나다.**

`HomeLocation`·`HomeRotation`은 `BeginPlay`에서 굳히는 상수라 상태가 아니다.
**"복귀 중인가"를 플래그로 저장하지 않고 매번 계산한다.**

```
returning = (now − LastSeenTime >= ReturnDelay) AND (homeDist > HomeArriveRadius)
```

집에 서 있으면 `homeDist ≈ 0`이라 **거짓** → 큰 구형으로 경계한다.
스폰 직후 플레이어를 한 번도 못 봐도 마찬가지라
[적 AI 1단계](2026-08-30-적-AI-1단계.md)의 합격 기준 1·2가 안 깨진다.

### 왜 상태 기계를 안 뽑았나

1단계 사양이 **"행동이 넷째·다섯째로 늘면 그때 뽑는다"**고 적어뒀고,
복귀가 정확히 넷째 행동이다(경계 · 추격 · 공격 · 복귀).

**그런데 뽑지 않았다.** 모드가 타임스탬프 하나에서 파생되기 때문이다.
분기가 하나 더 붙을 뿐이고, 1단계 사양의 무상태 규칙
(`거리는 매번 다시 잴 수 있다. 재면 되는 것을 저장하지 않는다`)이 그대로 유지된다.

**시야각이 붙거나 순찰이 생기면 이 판단을 다시 본다.**

| 변수 | 타입 | 기본값 | 인스턴스 편집 | 무엇 |
|---|---|---|---|---|

| `ReturnSightRange` | float | `300.0` | ✓ | 복귀 중에만 쓰는 작은 구형 반지름 |

## 완성 후의 호출 구조

```
BeginPlay
  → PlayerRef    = Get Player Character(0)
  → HomeLocation = GetActorLocation
  → HomeRotation = GetActorRotation
  → LastSeenTime = Get Game Time in Seconds
  → Think

Think
  IsValid(PlayerRef)?
    거짓 → PlayerRef 재획득 → Delay(ThinkInterval) → Think

    참:
      now       = Get Game Time in Seconds
      d         = GetDistanceTo(PlayerRef)
      selfLoc   = GetActorLocation
      toHome    = HomeLocation − selfLoc
      homeDist  = VectorLength(toHome)
      returning = (now − LastSeenTime >= ReturnDelay) AND (homeDist > HomeArriveRadius)
      radius    = returning ? ReturnSightRange : SightRange

      d <= radius ?
        참  → LastSeenTime = now
              d <= AttackRange ?
                참  → 몽타주 → ApplyDamage → Delay(AttackCooldown) → Think
                거짓 → AI MoveTo(TargetActor=PlayerRef, Accept=AttackRange−20)
                         OnSuccess / OnFail → Delay(ThinkInterval) → Think
        거짓 → returning ?
                참  → step = selfLoc + Normalize(toHome) × Min(ReturnStepDistance, homeDist)
                       AI MoveTo(Destination=step, Accept=HomeArriveRadius)
                         OnSuccess / OnFail → Delay(ThinkInterval) → Think
                거짓 → homeDist <= HomeArriveRadius ?
                         참  → SetActorRotation(HomeRotation) → Delay → Think
                         거짓 → Delay(ThinkInterval) → Think
```

**`Think`로 돌아가는 경로가 여덟이고 여덟 다 앞에 지연이 있다.**
1단계 사양의 핵심 규칙이 유지된다.

`Min(ReturnStepDistance, homeDist)`가 홉을 집까지 거리로 자른다 — **집을 지나치지 않는다.**

`LastSeenTime`을 `BeginPlay`에서 `now`로 초기화한다. 안 하면 `0`이라 시작하자마자
`elapsed`가 거대해진다. 집에 있으니 동작엔 지장 없지만 의미가 틀린다.

## 권한 / 수명 / 튜닝 값의 주인

- **싱글플레이.** 리플리케이션을 추가하지도 제거하지도 않는다
- **정리할 타이머가 없다.** `Set Timer`를 안 쓰고 `Delay`·`AI MoveTo`는 라텐트라

- **`HomeLocation`/`HomeRotation`의 주인은 레벨 배치 트랜스폼이다.**
  따로 지정하지 않는다 — **배치한 자리가 곧 집이고 배치한 방향이 곧 초기 방향이다**

## 추격 중 재평가 — 명령 68의 증분

**기준 1이 처음에는 통과하지 못했다.** `CHASE` 분기의 `AI MoveTo`가 래턴트라
플레이어를 목표 액터로 잡고 실행 핀을 물고 있었다. 플레이어 속도 600, 적 300이라
수용 반경에 영영 못 닿고, 경로가 유효한 한 실패도 안 난다. 그동안 `Think`가 안 도니
`SightRange`도 안 재고 `ReturnDelay`도 안 센다. **문이 열려 있으면 영원히 안 돌아온다.**

로그의 증거는 `12.42.26:748 CHASE` → `12.42.59:735 RETURN` 사이의 **33초 공백**이다.
그동안 `Think`가 0회 돌았다. `IDLE_WAIT`이 한 번도 로그에 안 나왔던 이유도 이것이다.

**문을 닫으면 복귀했던 것은 기능이 아니라 증상이었다.** 문간이 두 방을 잇는 유일한
NavMesh 통로라, 문을 닫으면 경로가 끊겨 `AIMoveTo`가 `OnFail`로 빠져나오고 그제서야
`Think`가 돌았다.

### 무엇을 바꿨나

- **`CHASE` 분기** — 래턴트 `AI|AIMoveTo`를 비래턴트 `AI|Navigation|SimpleMoveToActor`로
  교체. `Controller` = `GetController(self)`, `Goal` = `PlayerRef`.
  뒤에 `Delay(ThinkInterval)` → `Think`
- **`StopMovement` 셋** — `AI|Navigation|StopMovement`(`self` = `GetController(self)`)를
  `ATTACK` · `IDLE_WAIT` · `IDLE_HOME` 분기의 `PrintString` 바로 뒤에 넣었다.
  `SimpleMoveToActor`가 비래턴트라 아무도 안 멈추면 계속 걷는다

**`RETURN`과 `NO_PLAYER`에는 안 넣었다.** `RETURN`은 자기 `AIMoveTo`가 있고,
`NO_PLAYER`는 `PlayerRef`가 무효가 될 경로(플레이어 사망)가 아직 없다.

### 왜 짧은 홉을 안 썼나

`RETURN`이 쓰는 홉 패턴을 `CHASE`에도 쓰는 것이 대칭이지만 **이 레벨에서는 깨진다.**
플레이어가 1번 방, 적이 2번 방이면 직선 방향의 홉 목표점이 칸막이 벽 안에 떨어진다.
`RETURN`이 안 걸리는 것은 집이 항상 열린 바닥 위이고 직선 경로가 방 안에 머물기 때문이지
홉 방식이 안전해서가 아니다.

`SimpleMoveToActor`는 `FindPathSync`로 제대로 경로를 찾아 문간을 돌아간다.
`SetGoalActorObservation(*Goal, 100.0f)`로 플레이어가 100 이상 움직이면 알아서 재경로하고,
재호출 시 `AbortMove`를 `EPathFollowingVelocityMode::Keep`으로 하므로
**0.3초마다 다시 불러도 속도가 안 끊긴다.**
(`Engine/Source/Runtime/AIModule/Private/Blueprint/AIBlueprintHelperLibrary.cpp:493`)

### 명령 68의 합격 기준 넷

> 1. PIE에서 **문을 연 채로** 적에게 쫓기다 `SightRange` 밖으로 도망치면,
>    **7초 뒤 적이 복귀를 시작한다.**
> 2. PIE에서 적에게 쫓기는 동안 로그를 보면, **`CHASE`가 약 0.3초 간격으로 계속 찍힌다.**
>    30초짜리 공백이 없다.
> 3. PIE에서 적이 붙어 `ATTACK`이 뜨면, **적이 제자리에 서서 공격한다.**
>    플레이어를 밀고 지나가지 않는다.
> 4. PIE에서 `SightRange` 밖으로 나가면, **적이 즉시 그 자리에 선다.** 계속 걸어오지 않는다.

| 기준 | 상태 | 근거 |
|---|---|---|
| 1 | 통과 | 위 기준 1과 같은 로그. 문을 안 닫았다 |
| 2 | 통과 | `CHASE` 최대 공백 **0.31초**. `IDLE_WAIT`이 이 프로젝트에서 처음 로그에 나왔다 |
| 3 | **육안만** | 로그에는 `ATTACK` → `CHASE` 간격 1.5초(`AttackCooldown`)만 남는다. 밀고 지나갔는지는 화면에서만 보인다 |
| 4 | **전이만 로그** | `CHASE` → `IDLE_WAIT` 전이가 0.31초. **멈춰 서는 것 자체는 로그에 안 남는다** |

### 문의 의미가 바뀌었다

감지는 여전히 순수 거리이고 벽을 통과해서 본다. 그래서 **문을 닫아도 `SightRange 1200`
안이면 적이 문 앞에 서서 안 돌아간다.** 명령 68 이전에는 문을 닫는 것이 복귀를 일으켰다.

사용자가 `거리만 유지 — 문은 물리적 장벽뿐`을 골랐다. **시야각·라인 오브 사이트가
생기면 자연히 해결된다** — 그때 이 항목의 값이 올라간다.

## 이번에 부딪힌 함정 둘

### 함정 1 — 배치 순서

**첫 PIE에서 적이 145 거리에서도 반응하지 않았다.**

정적 분석으로는 못 찾았다. 그래프는 완벽했고 실행 사슬도 끊긴 데가 없었다.
**PIE 중에 `Enemy_Test`의 실제 변수를 읽어서 잡았다.**

```
ReturnSightRange   0     ← 300이어야 한다
ReturnDelay        0     ← 7
ReturnStepDistance 0     ← 300
HomeArriveRadius   0     ← 100
SightRange       1200    ← 옛 변수는 정상 상속
ThinkInterval     0.3    ← 옛 변수는 정상 상속
```

```
returning = (now − 0 >= 0) AND (0.25 > 0) = 참        ← 시작하자마자 계속 복귀 중
radius    = ReturnSightRange = 0
d ≈ 145  <=  0  거짓                                   ← 영원히 감지 실패
홉        = Min(0, 0.25) = 0                           ← 제자리로 이동 명령
```

**원인은 배치 순서다.** 인스턴스를 먼저 놓고 나중에 변수를 추가하면
그 인스턴스에 `0` 오버라이드가 박히고, 나중에 바뀐 클래스 기본값을 따라오지 않는다.
`MaxWalkSpeed 600 → 300` 때와 같은 종류다.

명령 66에서 인스턴스 값을 클래스 기본값과 **같게** 맞추자 오버라이드가 걷혔다 —
델타가 없어져서 외부 액터 파일이 커밋 시점과 바이트까지 동일해졌다.

**적을 새로 배치할 때는 변수를 다 만든 뒤에 놓는다.**

### 함정 2 — `AI MoveTo`의 도달 반경은 넘긴 값이 아니다

**적이 복귀는 하는데 집에 도착 판정이 안 났다.** `IDLE_HOME`에 못 들어가니
`SetActorRotation`이 한 번도 안 돌고, 적은 걷던 방향 그대로 서 있었다.
사용자가 눈으로 먼저 봤다 — `리턴하면 리턴한 방향에서 다시 문쪽 안바라보는거 같은데`.

로그가 그것을 그대로 뒷받침했다. `3_home`이 **소수점까지 고정**된 채 `RETURN`이
`ThinkInterval`과 같은 0.30초 간격으로 무한 반복된다 — `AIMoveTo`가 즉시 반환한다는 뜻이다.

```
[13.45.55:927] 106.648573  RETURN
[13.45.56:230] 106.648573  RETURN
[13.45.57:159] 106.648573  RETURN
[13.45.58:987] 106.648573  RETURN
[13.45.59:599] 106.648573  RETURN
```

**원인은 도달 판정 공식이다.**

```cpp
// Engine/Source/Runtime/AIModule/Private/Navigation/PathFollowingComponent.cpp:1328
const FVector::FReal UseRadius = RadiusThreshold + GoalRadius + (AgentRadius * AgentRadiusMultiplier);
```

`MinAgentRadiusPct = 1.1f`(136행), `bReachTestIncludesAgentRadius = true`(159행),
그리고 BP `AI MoveTo` 노드가 `bFinishMoveOnGoalOverlap = true`(`AISystem.cpp:28`)를
`SetReachTestIncludesAgentRadius`로 넘긴다(`AITask_MoveTo.cpp:21`).
`Enemy_Test`의 `CapsuleRadius = 35`이므로

```
AIMoveTo가 "도착"으로 치는 거리 = 100 (HomeArriveRadius) + 0 (지점 목표) + 35 × 1.1 = 138.5
블루프린트가 "도착"으로 치는 거리 = 100
```

**100과 138.5 사이가 사각지대다.** 적이 이 띠 안에서 멈추면 `AIMoveTo`는
"이미 도착했다"며 움직이지 않고 즉시 성공을 반환하고, 블루프린트는 `homeDist <= 100`이
거짓이라 다시 `RETURN`을 돌린다. `106.648573`이 정확히 그 띠 안이다.

한 번 성공했던 적이 있는데(`3_home 98.540625`) **운이었다.** 우연히 100 아래에서 멈췄다.

**고친 방법** — `HomeArriveRadius`(튜닝 값)를 키우는 대신 `AIMoveTo`에 넘기는
`AcceptanceRadius`를 `0.0`으로 낮췄다. 도달 반경이 `0 + 35 × 1.1 = 38.5`가 되어
블루프린트의 100 안에 안전하게 들어온다. 여유 61.5.
`0`이 안전한 것은 엔진이 `-1`만 "기본값 사용" 신호로 쓰기 때문이다
(`PathFollowingComponent.cpp:125` `DefaultAcceptanceRadius = -1.f`).

**`AI MoveTo`의 `Acceptance Radius`에 넣은 값은 그대로 쓰이지 않는다.**
에이전트 반지름의 1.1배가 더해진다. 블루프린트가 따로 거리 판정을 하고 있다면
**그 둘이 어긋나지 않는지 반드시 계산해본다.** 어긋나면 무한 루프가 되고,
에러도 경고도 안 난다.
