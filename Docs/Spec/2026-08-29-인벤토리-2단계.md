# 사양 · 인벤토리 2단계 — 손에 들기와 사용

2026-08-29 확정. [1단계 사양](2026-08-28-인벤토리-1단계.md)의 후속이자, **그 문서의 일부를 뒤집는다.**
구현은 커밋 `dc0b7ef`까지 반영돼 있다.

---

## 1단계에서 뒤집힌 것

**이 절이 이 문서의 존재 이유다.** 1단계 사양을 읽는 사람은 아래를 먼저 봐야 한다.

| 1단계 사양 | 2단계에서 바뀐 것 |
|---|---|
| `E`(사용)로 `Holdable`을 `hand_r`에 붙이는 **토글** | **토글이 없다.** 선택(`1`/`2`/`3`)이 곧 손에 드는 것이다 |
| `Holdable`만 손에 든다 | **아이템이 있으면 `nature`와 무관하게 전부 손에 든다** |
| `nature`가 "손에 드는지"를 정한다 | `nature`는 **`E`가 무엇을 하는지**만 정한다 |
| `HeldItemSlot`이 든 슬롯 번호를 기억한다 | **`HeldItemSlot`을 쓰지 않는다.** 손에 든 것은 상태가 아니라 `InventorySlots[SelectedSlot-1]`의 표현이다 |
| 합격 기준 2 — 칸 색과 초록 테두리 | 여기에 **손의 물건과 아이템 이름**이 함께 바뀌는 것이 추가됐다 |
| 합격 기준 3 — HP 회복과 칸 비우기 | 여기에 **`[E] Use` 표시**와 **손이 비는 것**이 추가됐다 |

사용자가 말한 모델은 **마인크래프트의 핫바**다. 칸을 고르면 그게 손에 들리고,
쓸 수 있는 물건이면 쓸 수 있다는 표시가 뜬다.

## 1단계 사양의 사실관계 정정

- **`InventorySlots`는 `DataTableRowHandle` 배열이 아니라 `Name` 배열이다.**
  칸에는 **행 이름만** 들어간다. 따라서 메시·색·이름을 얻으려면 매번
  `Get Data Table Row(DT_Items, rowName)`를 거친다.
- **`S_ItemDef`에 `mesh`(StaticMesh) 필드가 이미 있고 세 행 모두 채워져 있었다.**
  `Key_Stage1` → `Cube`, `Potion_Small` → `Cylinder`, `Ball_Test` → `Sphere`.
  손에 들 데이터를 새로 만들 필요가 없었다.
- **`IA_UseItem` 애셋과 `IMC_Inventory`의 `E` 매핑이 이미 있었다.**
  1단계에서 만들어두고 기록에 안 남긴 것으로 보인다. 조사 없이 갔으면 중복으로 만들 뻔했다.
- **`SKM_Quinn_Simple`에 `HandGrip_R` 소켓이 이미 있었다.**
  소켓 목록: `weapon_r_muzzle`, `foot_r_Socket`, `foot_l_Socket`, `HandGrip_R`, `HandGrip_L`.

## 범위

**만드는 것**

- 오른손에 아이템 메시 표시. 선택·습득·사용 어느 쪽으로든 칸 내용이 바뀌면 따라 바뀐다
- HUD가 폰의 `InventorySlots` · `SelectedSlot` · `CurrentHP` · `MaxHP`를 직접 읽는다
- 칸 색 채우기(`iconColor`), HP 바, 인벤토리 바 위 아이템 이름, `[E] Use` 표시
- `E` 사용 로직 (`Consumable`만 동작)
- `BP_ThirdPersonHUD.SelectedSlot`과 `SetSlot` 제거, PlayerController의 `Then 0` 가지 제거

**만들지 않는 것**

- **버리기(`Q`)** — 별도로 다룬다. 아래 `접어둔 것` 참조
- **1인칭 손 표시** — 3인칭 메시(`CharacterMesh0`)에만 붙인다
- 아이콘 이미지 — 색 사각형만
- `Key` · `Holdable`의 `E` 동작 — 아직 없다
- 스택(수량), 인벤토리 확장, 상호작용 인터페이스 — 1단계와 동일하게 안 만든다

**대상** — `Lvl_ThirdPerson` / `BP_ThirdPersonCharacter` / `BP_ThirdPersonHUD` /
`BP_ThirdPersonPlayerController`.

## 상태

`SelectedSlot`(1~3) 하나가 유일한 상태다.
**손에 든 것은 상태가 아니다** — `InventorySlots[SelectedSlot - 1]`의 표현일 뿐이다.

| 상태 | 소유자 | 타입 | 초기값 | 전이 |
|---|---|---|---|---|
| `InventorySlots` | 캐릭터 | Name 배열, 길이 3 | 전부 `None` | 습득 → 행 이름 / `Consumable` 사용 → `None` |
| `SelectedSlot` | 캐릭터 | int | `1` | `1`/`2`/`3` 키로만 |
| `CurrentHP` / `MaxHP` | 캐릭터 | double | `75` / `100` | 포션 사용 시 `Clamp(HP + healAmount, 0, MaxHP)` |
| `CachedCharacter` | HUD | `BP_ThirdPersonCharacter` 참조 | 없음 | 첫 그리기에서 한 번 잡고 유지 |

**`HeldItemSlot`은 이 설계에서 쓰이지 않는다.** 지울지는 아직 안 정했다.

### off-by-one 변환 지점

`InventorySlots`는 0부터, `SelectedSlot`은 1부터다.
**변환은 `SelectedSlot - 1` 한 번으로만 하고, 그 아래로는 0-based만 흐른다.**
현재 그 뺄셈이 있는 곳은 셋이며, 각각 그래프 안에서 **노드 하나**다.

- `BP_ThirdPersonCharacter.RefreshHeldItem`
- `BP_ThirdPersonCharacter`의 `IA_UseItem` 체인
- (예정) HUD의 이름 · `[E] Use` 표시

HUD의 칸 색 채우기는 `ForLoop`의 `Index`(0-based)를 그대로 쓰므로 변환이 없다.

## 규칙

- **선택 = 장착.** 칸에 아이템이 있으면 그 메시가 오른손에 보인다. 빈 칸이면 손이 빈다
- **`nature`는 `E`의 동작만 정한다**
  - `Key` — 아무 일도 없다
  - `Consumable` — `Clamp(CurrentHP + healAmount, 0, MaxHP)`, 칸을 `None`으로
  - `Holdable` — 아직 아무 일도 없다. 당분간 `Key`와 동작이 같다
- **`E`는 `Started` 핀에서 발동한다.** `IA_UseItem`의 `Triggers`가 비어 있어
  `Triggered`는 누르고 있는 동안 매 프레임 발동한다. 한 번 눌러 여러 번 먹게 된다.
  `IA_Interact`(F)도 같은 이유로 `Started`를 쓴다
- **손 갱신은 `RefreshHeldItem` 하나로 한다.** 호출 지점이 셋이므로 함수로 뽑았다
- **HUD는 폰이 단일 출처다.** `HUD.SelectedSlot`은 남아 있으나 아무도 안 읽는다
- **캐릭터를 못 잡으면 HUD가 아무것도 안 그린다.** 캐스트 실패 프레임에는 칸도 안 보인다

## 권한 / 수명 / 튜닝 값의 주인

- **싱글플레이.** 리플리케이션 없음. 기존 변수의 리플리케이션 설정을 건드리지 않았다
- `HeldItemMesh`는 캐릭터의 컴포넌트다. **아이템 액터를 스폰하거나 파괴하지 않는다** —
  메시만 갈아끼운다. 정리할 것이 없다
- Pickup 액터는 레벨에 손으로 배치, 습득 시 `Destroy Actor`. 1단계와 같다
- **아이템별 값의 주인은 `DT_Items`.** HUD의 배치·색은 HUD 인스턴스 변수
- **`HeldItemMesh`의 Relative Scale(`0.15`)만 예외적으로 컴포넌트에 있다.**
  아이템마다 다른 크기가 필요해지면 `S_ItemDef`로 옮겨야 한다

## 합격 기준

> 1. PIE에서 바닥의 공을 조준하고 `F`를 누르면, 선택된 칸이 파란색으로 채워지고
>    바닥의 공이 사라지며 **오른손에 공이 들린다.**
> 2. PIE에서 세 칸을 열쇠·포션·공으로 채운 뒤 `1`/`2`/`3`을 누르면,
>    세 칸이 각각 노랑·빨강·파랑으로 남은 채 선택된 칸의 테두리만 초록이 되고,
>    **오른손의 물건과 인벤토리 바 위의 이름이 그 칸의 것으로 함께 바뀐다.**
> 3. PIE에서 포션 칸을 선택하면 이름 아래에 `[E] Use`가 뜨고, `E`를 누르면
>    HP 바가 75%에서 100%로 늘고 그 칸이 빈칸으로 돌아가며 **오른손이 빈다.**
> 4. PIE에서 빈 칸을 선택하면 이름도 `[E] Use`도 안 뜨고 오른손이 비어 있으며,
>    `E`를 눌러도 아무 일도 없고 에러 로그도 없다.

**검증은 이 넷으로만 한다. 여기 없는 것은 "확인 안 됨"이다.**

## 옮기면서 AI가 정한 것 — 사용자가 말하지 않은 것들

1. **`HeldItemMesh`** — 컴포넌트 이름
2. **`RefreshHeldItem`** — 함수 이름
3. **`CachedCharacter`** — HUD 변수 이름
4. **손에 든 메시의 스케일 `0.15`.** `/Engine/BasicShapes/Cube`가 100×100×100cm임을
   레벨의 `BP_ItemPickup` 바운드(`min -50 → max 50`)로 확인했다. 스케일 1이면 1미터 큐브가
   손에 들린다. `0.15` = 15cm. **눈으로 보고 조절할 값이다**
5. **`NoCollision`** — 손의 물건이 캐릭터를 밀지 않도록
6. **부착 규칙: 위치·회전 `Snap to Target`, 스케일 `Keep Relative`.**
   스케일까지 Snap하면 4번의 `0.15`가 지워진다
7. **`Get Data Table Row`에 `DT_Items`를 직접 물린다.** DataTable 변수를 새로 안 만들었다
8. **캐스트 실패 시 HUD가 아무것도 안 그린다.** 빈 테두리만 그리는 대안보다 단순해서 골랐다
9. **채우기를 테두리 안쪽 `BorderThickness`만큼만 들여 그린다.** 여백을 더 두지 않았다
10. **HUD가 폰을 `BeginPlay`가 아니라 첫 그리기에서 잡는다.**
    HUD의 `BeginPlay`가 폰 빙의보다 먼저 돌 수 있다
11. **`AND` 대신 분기 중첩.** 블루프린트의 `AND`는 두 항을 다 평가하므로
    `Index < Length`와 `배열[Index] != None`을 묶으면 범위 밖에서도 배열을 읽는다

## 작업 중 확인된 `unreal-mcp`의 경계선

1단계 사양의 같은 절에 이어 붙인다. **1단계에 적힌 것 중 틀린 것이 하나 있어 정정한다.**

- **`E_ItemNature`의 열거자 순서는 MCP로 읽을 수 있다.**
  1단계 사양의 "MCP로는 못 읽는다"가 틀렸다.
  `DataTableTools.get_schema(DT_Items)`가 `"enum": ["Key","Consumable","Holdable"]`을 준다.
  **enum 애셋을 직접 읽는 툴이 없는 것이지, 그걸 쓰는 DataTable을 통하면 읽힌다**
- **`ObjectTools.get_properties`는 `UserDefinedEnum`의 프로퍼티를 하나도 못 읽는다.**
  이 부분은 1단계 기록이 맞다
- **`ObjectTools.get_properties`는 `..._C`(BlueprintGeneratedClass)로 안 읽힌다.**
  `Default__..._C`(CDO)를 넘겨야 한다. `BlueprintTools.get_default_object`가 그 경로를 준다
- **`read_graph_dsl`은 함수 그래프에서 정확하고, EventGraph의 입력 이벤트 체인에서 본체가 잘린다.**
  `EnhancedInputAction` 이벤트를 본체 없이 뱉는다. **수렴 간선(한 핀에 들어오는 두 번째 연결)도
  생략한다.** 노드 단위 확인은 `find_nodes` + `get_node_infos`로 해야 한다
- **`find_nodes`의 `title`은 짧은 부분 문자열로 건다.**
  `"Refresh Held Item"`은 빈 배열, `"Refresh"`는 잡힌다
- **다른 BP의 함수를 부르는 노드의 `type_id`는 `Class|<BP>|<Func>`다.**
  `find_node_types`가 그 형식을 목록에서 빠뜨리는데도 그게 작동하는 형식이다
  (`CallFunction|RefreshHeldItem`은 `does not exist`로 거부된다)
- **`Utilities|IsValid`는 `declaring_class`를 무엇으로 주든 항상 매크로로 해석된다.**
  순수 `IsValid`(bool 출력) 함수 노드를 만들 수 없다. 매크로 자체가 분기라
  `Branch`가 필요 없다
- **이 툴셋에 블루프린트 변수의 타입을 읽는 도구가 없다.**
  `list_variables`는 이름만, `get_properties`는 값만 준다.
  타입은 `get_node_type_pins`로 노드 핀을 통해 우회해 읽어야 한다
- **`get_variable_instance_editable`이 없다.** `get_variable_category`와
  `get_variable_replication`은 있는데 이것만 없다. **쓰기 호출의 응답 외에 확인 방법이 없다**

## 접어둔 것

### 버리기(`Q`) — 하기로 했으나 순서를 미뤘다

사용자가 제안했고 넣기로 했다. **`E`가 끝난 뒤에 한다.**

미룬 이유: (1) 합격 기준 4개에 없다, (2) `E`가 만드는 것(슬롯 읽기, 변환 지점,
칸 비우기)을 그대로 재사용한다, (3) 손에 드는 방식이 정해져야 버릴 때 손을 비우는
처리가 정해진다.

설계 시 알아둘 것:

- **`BP_ItemPickup`은 물리를 안 쓴다.** `bSimulatePhysics: false`, `Mobility: Movable`,
  `collisionProfileName: BlockAllDynamic`. `bEnableGravity: true`지만 시뮬레이션이
  꺼져 있어 의미가 없다. **스폰한 자리에 그대로 뜬다** — 그래서 "버릴 수 있는지 판단"이
  실제로 값이 있다. 안 하면 공중에 뜬 아이템이 생긴다
- 판단 방법 두 가지. **후자를 권한다**
  - `SpawnActor`의 `Do Not Spawn If Colliding` 하나로 — 노드 하나. 벽 속은 막지만 허공은 못 잡는다
  - 캐릭터 앞 지점에서 아래로 라인트레이스 — 노드 5개쯤. 허공·절벽까지 잡힌다
- 새로 드는 것: `IA_DropItem` 입력 액션 하나 + `IMC_Inventory`에 `Q` 매핑
- 습득이 오버랩이 아니라 `F` + 라인트레이스라 **버린 직후 자동으로 다시 줍히지 않는다**
- 레벨의 `BP_ItemPickup`은 액터 원점이 메시 중심이다(`z -50 → +50`).
  바닥 높이에 그대로 스폰하면 절반이 묻힌다
