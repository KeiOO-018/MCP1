# 사양 · 인벤토리 1단계 — 아이템 데이터와 인벤토리

2026-08-28 확정. 이전 프로젝트 **Project ICI**를 UE 5.8에서 다시 만드는 작업의 첫 단계다.
배경과 원본 분석은 [../ProjectICI5.8/](../ProjectICI5.8/) 참조.

사용자가 정한 전체 순서: **인벤토리 → 아이템 구조화·설계 → 아이템 배치·상호작용 → 적 AI → 전투**
이 문서는 그중 앞의 셋을 다룬다.

---

## 범위

**만드는 것** — 아이템 정의 표, 습득, 슬롯 보관, 사용. 아이템 3종(열쇠·회복포션·공).

**안 만드는 것** — 문·자물쇠, 적 AI, 전투, 스택(수량), 아이템 버리기,
인벤토리 확장/축소, 상호작용 인터페이스.

**대상** — ThirdPerson 계열. `Lvl_ThirdPerson` / `BP_ThirdPersonCharacter` /
`BP_ThirdPersonHUD` / `BP_ThirdPersonPlayerController`. 지금 슬롯 HUD가 물려 있는 곳이다.

## 핵심 목표

**아이템을 늘리는 데 그래프를 안 고치게 만든다.**

| 늘리는 것 | 드는 비용 |
|---|---|
| 아이템 **하나** 추가 (열쇠2, 큰포션, 파란공…) | **DataTable 행 하나.** 그래프 수정 0 |
| 아이템 **행동 종류** 추가 (던지기, 읽기…) | enum 값 하나 + `Switch` 가지 하나 |

원본이 아이템마다 클래스를 팠던 것(`ICI Stage 2 Key`, `ICI Stage 3 Key`)과 여기가 갈린다.
**Pickup 액터 블루프린트는 하나다.**

## 데이터 — 만들어진 상태 (커밋 `7366671`)

### `/Game/Inventory/E_ItemNature` (enum)

| 인덱스 | 이름 |
|---|---|
| 0 | `Key` |
| 1 | `Consumable` |
| 2 | `Holdable` |

행동이 갈리는 축이다. **아이템 개수가 아니라 행동 종류만큼만 늘어난다.**

> **확인 안 됨** — 인덱스 0/1/2. `unreal-mcp`에 enum 열거자를 읽는 툴이 없다.
> 순서는 `S_ItemDef`의 JSON 스키마에 `["Key","Consumable","Holdable"]`로 나온 것이
> 유일한 근거다. `Switch on E_ItemNature` 노드를 만들 때 핀 순서로 확인된다.
>
> 순서를 나중에 바꾸면 이미 저장된 DataTable 행이 조용히 다른 값을 가리킨다.

### `/Game/Inventory/S_ItemDef` (구조체, DataTable 행 타입)

| 변수 | 타입 |
|---|---|
| `displayName` | `Text` |
| `iconColor` | `Linear Color` |
| `mesh` | `Static Mesh` (오브젝트 레퍼런스) |
| `nature` | `E_ItemNature` |
| `healAmount` | `Float` |

### `/Game/Inventory/DT_Items` (DataTable, 행 구조체 `S_ItemDef`)

| Row Name | displayName | iconColor (R,G,B,A) | mesh | nature | healAmount |
|---|---|---|---|---|---|
| `Key_Stage1` | `Rusty Key` | 1 / 0.8 / 0.1 / 1 | `/Engine/BasicShapes/Cube.Cube` | `Key` | 0 |
| `Potion_Small` | `Small Potion` | 0.9 / 0.1 / 0.1 / 1 | `/Engine/BasicShapes/Cylinder.Cylinder` | `Consumable` | 25 |
| `Ball_Test` | `Test Ball` | 0.2 / 0.4 / 1 / 1 | `/Engine/BasicShapes/Sphere.Sphere` | `Holdable` | 0 |

### `/Game/Inventory/BP_ItemPickup` (Actor)

- 컴포넌트: `Mesh` (StaticMeshComponent, **루트**). 이것 하나뿐이다
- 변수: `ItemRow` — `DataTableRowHandle`, Instance Editable,
  기본 DataTable = `DT_Items`, RowName 비어 있음
- ConstructionScript: `ItemRow`의 행을 읽어 `Mesh`의 스태틱 메시를 설정한다

> **확인 안 됨** — `ItemRow`의 Instance Editable 플래그. 세팅은 했으나 읽는 툴이 없다.
> 레벨에 배치할 때 디테일 패널에 `ItemRow`가 보이는지로 확인된다.

### 입력

| 애셋 | 값 타입 | 키 | 하는 일 |
|---|---|---|---|
| `IA_SelectSlot` (기존) | Axis1D | `1` `2` `3` | 슬롯 선택. 스칼라 모디파이어가 1/2/3을 실어 나른다 |
| `IA_Interact` (신규) | Digital (bool) | **`F`** | 조준선 앞의 아이템 줍기 |
| `IA_UseItem` (신규) | Digital (bool) | **`E`** | 선택된 슬롯 아이템 사용 |

매핑은 전부 `IMC_Inventory`에 있다. **`IMC_Default`는 건드리지 않았다.**
`IMC_Default`가 쓰는 키는 WASD·방향키·Space·게임패드·`V`(시점 전환)뿐이라
`E`/`F`와 겹치지 않는다. 그래서 `IMC_Inventory`의 우선순위는 **0 그대로 둔다.**

## 상태

**`BP_ThirdPersonCharacter`가 인벤토리의 주인이다.**

| 상태 | 타입 | 초기값 | 전이 |
|---|---|---|---|
| `InventorySlots` | Name 배열, 길이 3 | 전부 `None` | 습득 → 행 이름 기록 / 사용(소모) → `None` |
| `SelectedSlot` | int | `1` | `1`/`2`/`3` 키로만. `0`은 쓰지 않는다 |
| `HeldItemSlot` | int | `0` | `Holdable` 사용 시 그 슬롯 번호, 다시 쓰면 `0` |
| `CurrentHP` / `MaxHP` | float | `75` / `100` | 포션 사용 시 `Clamp(HP + healAmount, 0, MaxHP)` |

**빈 칸의 표현은 `None` 하나뿐이다.**
원본은 `Item_Empty` bool과 `Item_Class = ICI_Empty` 둘로 빈 칸을 표시했다 —
어긋날 수 있는 상태가 둘이었다.

## 규칙

- **습득 위치** — 빈 칸 중 **가장 앞**(1→2→3)에 넣는다. 주울 때 칸을 고를 필요 없다
- **가득 찼을 때** — **안 줍는다.** 안내만 띄운다. 교체도 덮어쓰기도 하지 않는다
- **사용** — 선택된 슬롯 하나만 본다. 빈 칸이면 아무 일도 일어나지 않는다
- **`Holdable`은 토글** — 사용하면 `hand_r`에 붙고, 다시 쓰면 떼서 돌아온다.
  든 동안에도 슬롯은 차 있다

## 권한 / 수명 / 튜닝 값의 주인

- **싱글플레이.** 리플리케이션 없음
- Pickup 액터는 **레벨에 손으로 배치**한다. 습득 시 `Destroy Actor`. 스폰 주체 없음
- `Holdable`이 손에 붙은 상태에서 캐릭터가 사라지면 부착된 액터도 정리한다 (`EndPlay`)
- **아이템별 값의 주인은 `DT_Items`.** 슬롯 칸 수·크기·색은 HUD 인스턴스 변수

## 합격 기준

> 1. PIE에서 바닥에 놓인 공을 조준하고 `F`를 누르면,
>    선택된 슬롯이 파란색으로 채워지고 바닥의 공이 사라진다.
> 2. PIE에서 세 칸을 열쇠·포션·공으로 채운 뒤 `1`/`2`/`3`을 누르면,
>    세 칸이 각각 노랑·빨강·파랑으로 남은 채 선택된 칸의 테두리만 초록으로 바뀐다.
> 3. PIE에서 포션이 든 칸을 선택하고 `E`를 누르면,
>    HP 바가 75%에서 100%로 늘고 그 칸이 빈칸(테두리만)으로 돌아간다.
> 4. PIE에서 빈 칸을 선택하고 `E`를 누르면 아무 일도 일어나지 않고 에러 로그도 없다.

**검증은 이 넷으로만 한다. 여기 없는 것은 "확인 안 됨"이다.**

## 옮기면서 AI가 정한 것 — 사용자가 말하지 않은 것들

1. **아이콘을 텍스처가 아니라 색으로 한다.** 프로젝트에 쓸 수 있는 텍스처가 없고
   (`StarterContent` 미설치), HUD가 `DrawRect` 캔버스라 색이 그대로 맞는다.
   진짜 아이콘이 생기면 `DrawTexture`로 바꾸고 행에 `icon` 필드를 더한다
2. **스택(수량)을 안 넣는다.** 슬롯이 `Name` 하나면 끝난다. 필요해지면 그때 구조체로 바꾼다
3. **`SelectedSlot`을 HUD에서 캐릭터로 옮긴다.** 인벤토리 내용이 캐릭터에 있는데
   선택 상태만 HUD에 있으면 상태가 두 액터로 쪼개진다. HUD는 `BeginPlay`에서 폰을
   **한 번 캐시**하고 그리기에서 읽는다 — 프레임당 `Cast`도 `Get All Actors`도 없다.
   **2026-08-28 오전에 내렸던 결정을 뒤집는 것이다.** 그때는 인벤토리 내용이 없었으니
   HUD가 가져도 됐다
4. **`IA_Interact`(F) / `IA_UseItem`(E)를 새로 만든다.** 입력이 없으면 습득도 사용도 못 한다
5. **습득은 라인트레이스로 간다.** 사거리 **300** (원본과 같은 값).
   원본은 문만 라인트레이스이고 아이템은 오버랩 + `Enable Input`이라 경로가 두 개였다
6. **상호작용 인터페이스(`BPI_...`)를 만들지 않는다.** 지금 상호작용 대상이 아이템 하나뿐이다.
   라인트레이스가 `BP_ItemPickup`으로 직접 캐스팅한다.
   **문이 생기는 순간 그때 인터페이스를 뽑는다**
7. **Pickup에 콜리전 컴포넌트를 따로 안 단다.** 라인트레이스가 `Visibility` 채널로 쏘니
   스태틱 메시가 그대로 판정 대상이 된다
8. **`Holdable`은 토글.** 사용하면 붙고 다시 쓰면 떨어진다
9. **캐릭터에 `CurrentHP`/`MaxHP`를 추가하고 HUD에 체력 바를 그린다.**
   포션이 회복할 대상이 없으면 합격 기준 3을 확인할 방법이 없다. 최소한만 — 바 하나
10. **회복량 25, 시작 HP 75.** 한 번 먹으면 정확히 가득 차서 눈으로 확인된다
11. **`ItemRow`를 `DataTableRowHandle`로 한다.** 디테일 패널에서 **드롭다운으로 행을 고른다.**
    `Name` 문자열을 직접 치는 게 아니라 오타가 불가능하다 —
    원본의 문자열 비교 문제가 여기서 사라진다
12. **`displayName`을 영어로 넣었다.** 한글로 넣으면 MCP가 읽어 터미널에 뱉을 때 네모가 된다.
    게임 화면 표기는 나중에 한 번에 바꾸면 된다
13. **새 애셋은 전부 `/Game/Inventory/` 아래.** 기존 폴더에 섞지 않는다

## 작업 중 드러난 `unreal-mcp`의 경계선

이 프로젝트에서 계속 부딪힐 것들이다. 전부 터미널이 툴셋 소스를 읽거나
실제 호출해서 확인한 것이다.

- **`UserDefinedEnum` / `UserDefinedStruct`를 만들 수 없다.**
  `BlueprintTools.create`는 애셋 클래스가 `unreal.Blueprint`로 하드코딩돼 있고
  `asset_type`은 **부모 클래스**로만 쓰인다. 만드는 툴도 편집하는 툴도 없다
- **enum을 읽을 수도 없다.** 열거자 목록을 반환하는 툴이 없다.
  이름은 다른 애셋의 JSON 스키마에 딸려 나오고, **인덱스는 어떤 툴도 주지 않는다**
- **배열 프로퍼티에 원소를 덧붙이는 툴이 없다.** `ObjectTools.set_properties`는
  값을 통째로 교체한다. 인스턴스 서브오브젝트(예: `InputModifierScalar`)가 든 배열을
  다시 쓰면 **기본값으로 새로 생성될 수 있고, 그러면 배열은 멀쩡해 보이는데 값만 죽는다**
- **`InputMappingContext`의 `Mappings` 프로퍼티는 비어 있다.** 진짜 데이터는
  `defaultKeyMappings.mappings`에 있다. `Mappings`만 읽으면 컨텍스트가 빈 줄 안다
- **`BlueprintTools.create`에 `/Script/Engine.Blueprint`를 넘기면**
  `Unable to create asset ...`라는 일반 오류가 난다. 인자가 문제라는 힌트가 없다.
  부모 클래스(`/Script/Engine.Actor`)를 넘겨야 한다
- **`Get Data Table Row` 노드의 Data Table 핀은 리터럴이어야 한다.**
  `UK2Node_GetDataTableRow::GetDataTableRowStructType`가
  `DefaultObject != nullptr && LinkedTo.Num() == 0`을 요구한다
  (`K2Node_GetDataTableRow.cpp:145`). 선을 연결하면 Out Row가 와일드카드로 남아 컴파일이 안 된다
- **`--append-system-prompt`로 터미널 세션의 역할을 지정해야 한다.** 그러지 않으면
  터미널 안의 에이전트가 이 `CLAUDE.md`를 읽고 **자기도 명령문을 작성해서 내놓는다.**
  실행하지 않는다
